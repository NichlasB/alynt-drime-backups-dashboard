## Source findings: the gap is exception provenance, not a retry defect

| Current uploader source | Exact constraint |
|---|---|
| `trait-registration-admission-root.php` | A normal false transaction return calls finish then private qualification with null auth/intent/physical observations. A transaction exception reaches the broad outer catch, returns false, and finally erases; it does not qualify history. Setup/auth/final-callback exceptions share that outer refusal, so the broad catch cannot identify a native failure boundary. |
| `trait-registration-admission-storage.php::admission_write()` | Reserves the sole attempt before prepare/bind. Marks DML immediately before execute. | `trait-registration-admission-transaction.php` | BEGIN/COMMIT are marked before query; true returns are captured before separate pinned session/idle checks. All-ten readback precedes COMMIT. Failed idle verification is not verified commit. |
| `trait-registration-native-outcome-session.php::finish()` | Cleanup is once-consumed; only definite pre-COMMIT ownership may attempt rollback. It detaches/closes the exact owned writer and seals history. Unknown BEGIN/COMMIT/rollback is not retried. |
| `trait-registration-native-outcome-capture.php` | Pre-call mark means may-have-been-sent; raw unknown survives a throw, raw false stays false with unknown acknowledgement. No native current guards/accepted_at are recorded. |

## Selected next contract: same-root closed failure bridge

Do not create another outcome DTO, generic classifier, provider or phase machine.
Reuse the existing private closed qualification helper and exact source capture.
The next separately approved source slice may normalize **only the synchronous
call to admission_transaction()** into returned-true, returned-false or thrown.
This is internal control flow, not a new public result, stored schema or API.

1. Keep original POST/auth/role-only query fences, issuance before protected
   capture, full command construction/authorization and original origin retention
   unchanged. No extra reads, nonce issuance, clock start or identity construction.
2. Place the narrow native-call boundary only after the original complete pin,
   writer creation/metadata and pre-BEGIN small/full guards have succeeded.
   It must not encompass setup, construction, guard callbacks, qualification or
   final erasure. Standalone behavior remains closed and non-authorizing.
3. Observe a throw only as loss of a normal transaction return. Do not inspect or
   export exception text, errno, SQLSTATE, SQL, trace or payload to infer outcome.
   Do not change raw/event/ack maps to fill missing observations. The current
   actual native observation sites, not a catch label, establish history.
4. Route returned-false and thrown calls to one explicit **normal-flow** closed
   epilogue: existing finish once, then qualification at most once from the same
   retained root. No classification, authentication or fallback in catch/finally.
   If cleanup, exact pin, seal, clock or qualification is unavailable, return false
   and erase. Outer catch remains the refusal for errors outside that boundary.
5. Failure qualification keeps auth/intent/physical null, not false-to-true repairs.
   The root-derived unreentered observation may still be checked. No new final
   authentication callback runs after a native failure; no current acceptance is
   inferred from earlier guards, a receipt, unchanged user ID or client close.
6. Regardless of historical label, this failure branch returns false. Its private
   DATA result is neither exported nor retained after the root exits. All
   diagnostic/read/retry/storage/dispatch/execution/authority flags stay false.
   The existing successful path still requires committed history AND all original
   current gates; preserve standalone nine/joined ten nonce order and one command
   nonce creation. A final callback throw is not a native transaction failure.
7. Outer finally remains cleanup/consume/erase/filter-and-error-handler restoration
   only. A repeated finish cannot promote the seal or repeat I/O; it is not a
   second recovery attempt. Consume qualification even when no usable result
   exists. Reentry or restored private data never resets loss/attempt latches.

The proposed boundary is not implemented here. It retains no new sensitive data
past the existing request lifetime and adds no work under row locks. Full writer
bytes/original nonce remain private only as already needed for final pin/guard
checks, and erase on every exit. No nested consuming owner or runtime reflection.

## Conservative uncertainty and provenance rules

Keep historical interpretation, client release and current authorization separate.
Reuse existing exact graph/raw/ack validators; do not fork their outcome precedence.
No native adapter may synthesize acknowledgement no. A pre-call send marker proves
only that source reached the call boundary, never that bytes reached the server.

| Valid original capture after cleanup | Closed interpretation and limit |
|---|---|
| No DML mark, no ambiguous BEGIN/rollback, explicit never-created or valid owned cleanup | not_written by this attempt only; attempt1/prepare/bind failure is not a DML send. No retry certificate. |
| BEGIN send; false/throw, or true ack without verified ownership | unsupported; never infer not_written from missing DML or a successful close. |
| DML may-have-sent; rollback acknowledged AND pinned idle verified | rolled_back, even when execute was unknown. An execute exception alone is not uncertainty after a verified rollback. |
| DML may-have-sent, no COMMIT send, no verified terminal outcome, no unsupported rollback ambiguity | uncertain; source history only. Successful close does not prove what happened at the server. |
| COMMIT send; false/throw, or true ack without verified idle | uncertain; no rollback/reconnect/readback-after-close to make the result favorable. |
| Rollback sent without verified ack AND idle | unsupported has precedence; not promoted to the supported uncertain lane. |
| Verified readback/COMMIT ack/idle, followed by close/guard failure | Preserve committed history; acceptance/release may fail independently. Do not relabel rollback/no-write. |
| Invalid/reopened/missing capture, contradictory ordinals/raw/acks, changed origin/any ID/full bytes, expiry, reentry or remaining owned slot | Unavailable attributed qualification. Erase; do not repair evidence or choose a favorable label. |

Raw true means the API returned true, not a server-quiescence or durability
certificate beyond the existing verified history contract. Raw false and unknown
remain distinguishable, both with unknown ack. No result/affected-row counter,
poisoned phase, elapsed wait, later receipt or missing row substitutes for original
call-site observations. Client release requires actual source-derived seal/empty
slots and positive close for a created writer; a missing handle is insufficient.

Preserve the existing original <10-second half-open acceptance window,
nonregressing monotonic/UTC observations and original command expiry through
qualification. I/O may overrun: rejection is not cancellation or a new root window.
No20-second/read-phase extension. Reuse origin4096/depth6/nodes256, complete IDs
12..128 and aggregate16384/depth8/nodes512 caps; reject rather than truncate/remint.
Do not put full writer tuples or handles into a minimal primitive evidence record.

## What could establish real unknown-wire evidence later

An isolated source control that throws at a native API seam is **simulated
uncertainty**, even if real surrounding WordPress or SQL ran. A genuine physical
proof needs an independent, bounded test-only witness of the exact original owned
writer/call and lost acknowledgement, plus the unmodified owner's observations.
It must distinguish API failure from server receipt, completion and later state.
Server-side fixture reconciliation can establish what happened in that experiment;
it must not be fed back into runtime qualification or treated as current authority.

No physical experiment is approved by this design. Before such work, require a
separate exact Plugin Tester/disposable target and owned-fixture confirmation,
read-only scope preview, baseline application checksums, bounded deadlines and
independently verified fixture cleanup. A shared LocalWP database restart, global
network disruption, arbitrary process kill, borrowed-auth termination, credential
change or production endpoint redirect is out of scope. Any proposed transport
harness/profile change needs its own design and approval; do not weaken the fixed
MariaDB loopback/physical identity checks merely to enable fault injection.

Required future case separation: unknown execute followed by verified rollback;
unknown execute without a verified terminal result; lost COMMIT response;
acknowledged COMMIT followed by failed idle check; ambiguous BEGIN; ambiguous
rollback; and close failure independent of history. Do not claim all cases from a
single killed connection, timeout, reflected field or catch. A worker crash cannot
produce a same-request postrelease qualification: audit cleanup is operational
evidence only. Even independently observed receipt/absence cannot prove safe retry
for a still-running writer. If safe bounded physical evidence cannot be obtained,
record the blocker and keep the diagnostic veto closed.

## Guarded failure means refusal, not an observer grant

This selected source slice does **not** add fresh current guards after failure.
Any later policy allowing uncertain diagnostics requires separate design approval
after real provenance/release proof. It must use the same original actor/session/
cookie/installation, unreentered root and complete pin, preserve the original
clock/expiry, and separately establish both read-intent nonce domains before any
lookup ID/protected observation. A failed or unperformed guard cannot be retried
into success, imported from mutation intent, or reconstructed from a stored receipt.
No currently synthetic diagnostic_candidate_only result opens that policy.

No observer transaction, lookup UUID, read nonce, repair/retry, durable closure,
server quiescence, grants, activation, effects or rollback is introduced. Memory
consumption is not durable admission closure; a negative observation at a later
barrier is not absence forever. Dashboard remains read-only relative to clients
and Drime; no new action/capability, wire contract, UI, AJAX, REST or cron loading.

## Next gated implementation and falsifiability

**local-only V2.3 Fixed Native Failure Boundary and Closed Qualification Safety
Foundation**, isolated API tests only, is the preferred next slice. It implements
the narrow same-root failure bridge above, not a new redundant DATA layer or
physical fault harness. Fresh approval required; actual authentication, storage,
native execution, production wiring, grants, observation, activation and rollback
remain disabled. Keep runtime capture/transaction/cleanup bodies unchanged where
possible; any discovered broader change must stop for a revised approval boundary.

Tests must run the actual shared root/qualification and native capture/transaction/
storage/cleanup source bodies at their respective seams, explicitly identifying
every API double. Prove the composed thrown path, not just disconnected positive
root tests plus a separate throw-capable transaction harness. Child workers remain
extension-free for native API doubles; no WordPress bootstrap or database access.
No test-only provider or public fault switch may enter runtime source.

Required assertions/controls for that implementation:

- Known positive commit still accepts; an always-unavailable owner/qualifier fails.
  Normal false and thrown native paths qualify once, then refuse, erase and bar
  replay. Force the throw before/after each relevant native acknowledgement and
  statement cleanup; distinguish each expected injected error from assertion errors.
- A removed narrow bridge fails an assertion requiring its private qualification;
  thrown failures cannot pass just because all tests expect false. Native send/ack
  captures must come from actual source bodies, not assigned phases/results.
- Exact unknown BEGIN/rollback precedence, verified rollback after unknown execute,
  lost COMMIT ack and ack-without-idle stay separate. No-marker prepare/bind failure
  is not sent; false-to-no, missing send or fabricated idle each fails a control.
- Native false/throw paths run no new current guards: original guard counts stop
  before final callbacks, auth/intent/physical remain null, uncertain diagnostics
  remain false. Removing either restriction must fail a meaningful assertion.
- Throw from setup, original authorization, capture/construction, qualification or
  final callbacks never enters the native-failure bridge or manufactures history.
  Malformed/stale/wrong-domain/unauthorized input still causes zero protected I/O.
- Seal/empty-slot/original full pin/all-ten-ID/clock/reentry/one-shot gates are
  independently falsified. Late callbacks cannot reopen raw history. Same borrowed
  auth handle stays untouched; no write-capable handle or result escapes.
- Keep existing nine/ten guard-order and one nonce assertions, positive history,
  privacy/final-class/production-unloaded checks and independent cleanup counters.
  Every temporary semantic mutation must be assertion-killed and exact-hash restored.

These tests prove isolated source composition, not genuine authentication, physical
transactions, real network loss, server completion or Database Review. A later
owned proof and any real transport experiment remain separately scoped gates.
