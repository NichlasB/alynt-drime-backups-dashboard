## Three identities, not a version-normalization shortcut

Keep separate (1) binary/build identity and --version, (2) administrative SQL
VERSION(), (3) actual PHP7.4 mysqli_get_server_info/raw handshake identity plus
genuine core db_version/has_cap/determine_charset outputs. An RPM recipe/version
label cannot prove any equality between these. UBI is selected as a plausible
unsuffixed-build candidate, not a measured unsuffixed build. No --version override,
proxy/handshake rewrite, suffix stripping, loose/prefix comparison or fabricated
expected string is allowed.

Known prior evidence: PHP7.4/mysqlnd against the newer-server lab observed
5.5.5-10.11.18-MariaDB-ubu2204 while SQL VERSION() was10.11.18-MariaDB-ubu2204.
Pinned core6.0 keeps the numeric prefix and may select unicode_ci for empty
DB_COLLATE. See the [approved lab-only collation decision](SOURCE_POLICY_MINIMUM_COLLATION_COMPATIBILITY_DECISION.md).
That exception binds only its exact existing server image/frame/receiver/context;
it does not admit this new image. Do not broaden its constructor's fixed evidence
map or silently relabel a new private scope as default legacy qualification.

Default [transport server map](../includes/class-source-policy-transport-profile.php)
still requires10.6.23-MariaDB for core6.0; [session validator](../includes/class-source-policy-bootstrap-evidence.php)
still requires unicode_520_ci outside the bound M-lab exception; physical schema
stays InnoDB/unicode_520_ci. If the candidate's actual raw/core outputs conflict,
record a definite refusal, not success. Any proposed default API/build equivalence
or helper-derived collation policy is a separate explicit acceptance decision
after observation, preserving exact source/receiver provenance and negative tests.
Engine-row coverage and default-contract eligibility must be reported separately.

## Non-vacuous validation and accounting

Future isolated tests must include an actual accepted fixed metadata/profile
control and refusal of each wrong digest/config/arch/entry/volume/path/size/owner/
phase/source/run/receipt field. Removing a required guard must kill the assertion,
not merely cause startup failure. Driver-free tests cannot claim native resource,
authentication, SQL or physical release proof; version-only feasibility cannot
claim a successful connection or M qualification. New bytes/tuple invalidate
affected source-image receipts; never transfer previous physical evidence.

This design advances the required legacy M candidate/runner decision, not the
physical row itself. After validation/publication/exact-head CI it is campaign
milestone4/10, with ordered native qualification attempts unchanged7/10; evidence
commits and metadata lookups are not extra milestones. Prior campaign ceilings
(ten native attempts, three evidence-backed repair cycles per distinct blocker)
are not reset or extended. Deferred Windows minimum observer/toolchain, new
host installation, support changes, production/form/provider admission, grants,
activation/rollback and package/release/deploy remain outside scope.
