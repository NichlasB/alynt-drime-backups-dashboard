At most3 owned users (two capable users and one incapable),2 roles,2 sessions/user,

user/role/session value is primitive, finite and bounded; no external identity or

adba_row reads that whole table. They CANNOT be reused unchanged once role options

seed/read predicates, preserve role/non-target rows byte-for-byte, and qualify the
fixed peer-SQL allowlist without broadening application SQL. Do not hide the extra
rows in another ambient options binding or silently drop/reseed roles between
authentication and policy capture. Existing receipts remain historical; the new
mixed-options helpers require isolated source-backed regression coverage.

Fixture policy≤16KiB and each other fixture payload≤4KiB; reject unexpected rows,
autoload or cache content rather than trimming observations. Authenticated setup,
request reads, policy commands and independent verifier reads are separate ledgers.
Do not spend/reset policy bootstrap's8 stages/20s/16 credits on auth. Preserve
native2s/3s connect/read,3s statement/1s lock and existing whole-job/process/output/
cleanup limits. Exact auth query counts require measurement, not invented expected
totals; unexpected paths/overflow stop before qualification. No new native attempt
or budget granted here. Numerical fixture limits are proposed maxima, not observed

Use fresh owned request processes to avoid cached current_user/role/salt/session

owned tables/accounts absent, query observers released, handles closed and independent
held-live/post-exit sessions/transactions zero. Cleanup failure prevents another

## Ordinary-visibility composition proposal — a real new approval boundary

PHP private constructors/fields are not cross-class friends. Current fixture
Reflection, Closure::bind/setAccessible, mutable exported DTOs or an always-refusing
factory cannot establish a real builder. Do NOT simply make constructors public.

Recommend a narrow result-only, UNREGISTERED request-scoped command boundary in
the existing Guarded_Entry class, separately approved for the next foundation.
It is a new internal callable surface, NOT authorized/implemented by this design.
Existing create() factories stay unavailable; no hooks/routes/form/writer switch.

1. A fixed command wrapper admits capability, nonce, canonical request and exact
   record before privately creating its operation-local entry/root. View keeps
   its existing capability/type/record policy; no arbitrary operation selector.
   The exact Site_Repository is code-owned, not a caller callback/object/handle.
2. Each existing class owns its narrow construction/binding method, because only
   that class may legally access its private constructor/fields. Cross-class
   methods can be PHP-public but must require the SAME private, unexported root
   identity, exact peer roles and a consumed one-time assembly phase. No separate
   token framework, caller manifest, generic service locator or ready/facts setter.
3. Root privately retains receiver/query/context/adapter/provider; fixed leaf
   construction opens nothing. Bind receiver/query identities before context
   source capture. After guards/source checks the context PUSHES its frozen private
   frame/binding to the exact registered receiver once; no credential getter or
   caller-supplied frame. Preserve the existing source-first capture and actual
   initializer-owned active transition. Do not pre-read config to break the cycle.
4. Never return root/permit/provider/context/query/adapter/receiver or a write-capable
   handle. Only existing mode/revision, literal results or projected error codes
   escape. Root cannot clone/serialize/restore; revoke assembly before fallible
   cleanup, drop all secrets/peers and consume before callbacks/reentry.
5. Ordinary isolated API tests must call the actual guarded boundary and actual
   class-owned methods, with no Reflection/closure visibility bypass in the positive
   construction path. Reflection may inspect terminal state only, not supply it.
   Wrong/unissued/closed root, foreign peer, duplicate role/bind/reentry, extra frame,
   forged model and constructor access refuse without effects or handle export.

This proposes a bounded construction contract, not defense against hostile
same-process PHP code wielding Reflection. No runtime hash/nonce can turn arbitrary
co-resident code into a trust-isolated adversary. Future genuine proof must use
the actual implemented composition, not the old fixture graph in its place.
