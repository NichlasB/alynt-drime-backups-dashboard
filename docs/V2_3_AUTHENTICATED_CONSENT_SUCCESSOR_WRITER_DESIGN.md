## Decision and Approved Boundary

Prefer a separately versioned, mutable, initially closed successor in the existing dedicated safety option, with a durable pending-writer barrier in that same row. Authenticated consent, immutable receipts and cooperating semantic writers must share monotonic permission fencing. Closing consent before a separate write is necessary but insufficient: that write must also be serialized against barrier completion and any later grant. Do not solve this by a global option filter, another independently writable permission boolean, or promoting fixture provenance.

This R3 design approval covers dashboard documents only. Uploader source is read-only; no runtime code, schema, SQL, actual users/options/cron, fixture, permissions, handler, production wiring, grant creation, activation, rollback, version, release or deployment changes. Dashboard remains `0.1.77`, uploader `0.5.25`. No site access, LocalWP/Novamira operation or backup is needed. Numeric schema version and exact serialized field layout remain a separate implementation review, not a deployed decision here. Single-site only; no new capability, secret, action, protocol or multisite support.

## Candidate Successor Invariants

Use a new strict validator, not relaxed schema-4/5 acceptance. Require exact keys/types, fixed validated existing site scope, bounded canonical encoding, non-autoloaded storage, authoritative reads and exact-byte writes. Missing, corrupt, unsupported, autoloaded or wrong-site state rejects without initialization, normalization or repair. No constructor/getter/status/receipt operation migrates or generates an identity. Default-off construction has zero reads/writes/hooks; inherited initialize, claim, activate, dispatch and rollback APIs remain denied.

| Private record group | Required invariant |
| --- | --- |
| Mutable model | Current storage generation, schedule revision, enrollment binding, claims, authority and dispatch. Preserve cadence/due and protected work. Authority remains false; active lifecycle/dispatch creation is not part of the next foundation. |
| Lifecycle | Closed/disabled or draining with consent false initially. Future preparing consent requires the separately authenticated grant path; no active or verified-legacy inference. Keep `new_model`/unknown history untrusted. |
| Closed checkpoint archive | Prefer one frozen complete schema-5 checkpoint, including its original protected state and segregated schema-3/4 archive, validated independently of mutable live fields. Never recursively archive successor snapshots. Reject duplication/size/depth overflow rather than drop evidence. This trades capacity for auditable immutability; no archive compaction is approved. |
| Upgrade receipt | Exact original site/binding/epoch, checkpoint consistency digest, resulting epoch and bounded UTC time. A distinct closed-upgrade record, never authenticated grant provenance or a promoted fixture receipt. Digest is consistency checking, not a signature against privileged writers. |
| Authenticated grant | Initially null. Only a future closed authenticated writer can atomically create preparing provenance plus consent/receipt at the exact current binding/epoch. Source/path marker, ID or structural validation alone is not authorization. Closure clears the current grant pointer while retaining the grant's receipt. |
| Transition receipts | Immutable bounded ID, purpose/domain, canonical digest, expected/result epochs, commit time and ledger outcome. Separate namespaces for authenticated requests, internal writer closures and untrusted archived fixtures; reject retained cross-domain ID collisions. No raw request/session/nonce/cookie/token/verifier or unnecessary actor identifier. |
| Pending writer | Null or one exact bounded operation descriptor: server ID, allowlisted writer kind/target, original and closure epochs, current binding, allowlisted changed-field names plus target precondition/result digests, closure receipt identity and bounded start time. No raw credentials, secret delta values or settings snapshot stored. It is a durable admission barrier, not an executable request or expiring permission lease. |
| Writer completion | Separate immutable bounded terminal outcome referring to the original pending ID and closure receipt: secondary committed or explicitly abandoned/failed-closed. Unresolved is a nonterminal observation/error, never permission to remove pending. Never rewrite a closure receipt to mean settings were saved or a scan occurred. |

An explicit guarded upgrade accepts only a valid existing schema-5 checkpoint at the submitted epoch. Earlier supported fixtures must first use their existing explicit closed migration; absent-row bootstrap remains unapproved. Copy protected work/history unchanged, advance storage generation, permission generation and schedule revision once, keep consent false/grant null, and reject unfinished source work rather than manufacture draining migration. A rerun observes the matching upgrade without resetting newer mutable epochs/receipts; different origins conflict. The old closed validator is unchanged and intentionally rejects the successor.

Keep total encoded state at most 128 KiB and depth 16, retaining at least the existing 4 KiB closure reserve and a combined 50-entry optional receipt-history budget across archived and new namespaces. Count archived entries before admitting new history; a full fixture archive can therefore block grants, not justify erasure or a larger cap. Mandatory retained last/grant/closure/completion slots also count toward the byte bound. The reserve must be measured against worst-case new mandatory closure/pending/completion records, including the grant being closed: 4 KiB is a floor, not an assumed proof of fit. Bound every new record before storage; reject upgrade/grant/writer admission until byte and counter reserve is demonstrated. Do not evict the frozen archive, retained history or current grant/closure evidence. Optional previous closure archival may be omitted at full history only as in the existing bounded model, never deleting protected receipts.

Every new permission/semantic transition advances permission generation and schedule revision; every persisted state change advances storage generation. Writer finish/abandon also advances permission generation/revision to fence stale finishing attempts, even if no setting changed. Before a begin operation reserve increments for begin, terminal closure/finish and one emergency closure, plus their mandatory receipts; reject exhaustion before incrementing. The final available closure may retire the row permanently closed. No wrap/reset, silently refreshed expected epoch, pruning-for-space or elapsed-time recovery. Reserve cannot cure unavailable storage.

## Authenticated Request and Receipt Separation

Preserve the established capability/session, POST, distinct issuance/command/read nonce, fixed-site, exact scalar parsing and 300-second independent deadline requirements. Future authenticated domains must be new and explicitly versioned, not the adapter's fixture nonce/receipt domains. Bind the complete server-issued canonical intent, including purpose, original binding/epoch, ID and times; a semantic writer's intent must also bind its allowlisted target and exact proposed change/preconditions. Never derive trust from a posted provenance flag, actor, callback, target option name or replacement binding.

The reviewed adapter/factory must close over real authoritative providers and the specific store; arbitrary injected ports remain test seams, not a security sandbox. Authenticate before private reads and at each attempted write. Revalidate actual cookie/session/capability rather than cached current-user facts: the real-core proof showed nonce validity alone can survive session revocation. Original expected epoch and deadline remain fixed for at most three CAS attempts. Capability changes after the final check are still not atomic with storage; no claim of instantaneous role-based revocation.

Future grant is preparation only: require no pending writer/uncertainty, current authoritative semantic context and reviewed writer readiness, preserve capacity, then one CAS records grant/receipt with authority false. Do not implement it in this design or the next closed-only foundation. An authenticated revoke closes without requiring old pairing, grant eligibility or the old grant session. Rebind first closes old consent; the live binding changes only after the separately authorized semantic writer succeeds. Failed rebind keeps closed old context, never pretends new pairing succeeded. Upgrade and internal writer closure have distinct purposes; they cannot borrow a grant nonce or dashboard signature.

After current authentication and valid original intent, retained same-ID/same-digest requests observe only; changed purpose/digest/domain conflicts. Expired command consumption rejects even if retained. Fresh independent receipt-read intent can observe the old ID without renewing/replaying it. A different currently authorized administrator may reconcile site-owned receipts; logout does not revoke a committed grant. Read results are bounded current/superseded/not-found/unresolved observations with execution flags false, no private snapshot or reusable permit. Closure, secondary completion and owned-effect results remain different facts. Unknown acknowledgement never authorizes replay, a new ID or a dependent write.

## Closed-First Participating Writer Protocol

The preferred candidate is **durable begin closure followed by a short serialized local storage transaction**, not optimistic rechecks around an unconditional `update_option()`. This introduces a new storage/backend boundary requiring separate implementation and SQL/process approval; it does not broaden the current CAS adapter. Initial support must explicitly prove transactional row locking on a supported engine/connection, reject unsupported storage/cache/drop-ins, and never silently fall back to separate writes. No transaction runs HTTP, cron, hooks, user callbacks, logging or queue/upload work.

1. Authenticate/authorize the original writer purpose, validate the exact bounded delta, and read authoritative existing safety and target rows. Sanitation prepares an intended change but is not a successful write. No missing-row creation or identity bootstrap. A no-op is observed only, never permission renewal.
2. One safety-row CAS closes consent, advances epochs/revision and stores the pending descriptor plus immutable closure receipt. Every competing grant and semantic writer must reject pending state. If closure fails or acknowledgement is uncertain, stop: prior consent may remain; no dependent write or “disabled” claim. Reconcile the original operation ID through fresh authorized observation.
3. After confirmed closure, freshly reauthenticate/authorize the original writer purpose immediately before entering its bounded transaction. On one connection, lock the safety row first and the fixed target row second, then validate exact pending ID/epoch/site/binding, authoritative target bytes, the original intent scope/deadline against the current clock, and intended delta. All participating secondary writers use the same lock order. A pre-lock storage/context observation is not sufficient. Lock waits/deadlocks/timeouts abort with no automatic fresh intent. Capability/session changes after the pre-transaction authentication remain a documented race: the local row locks do not lock WordPress users/roles, and arbitrary authorization hooks must not execute inside the storage transaction.
4. Conditionally write the fixed target from its exact current bytes, verify expected row outcome, and persist terminal writer completion plus removal of that exact pending descriptor in the same transaction. Rebuild the resulting binding through the reviewed raw-context contract, never from a posted hash; loss of pairing keeps the historical binding non-admitting until an explicit valid replacement. Advance fencing counters; keep consent absent and admissions closed. No-op SQL results require authoritative equality, not truthy success. Commit before any cache publication or successful UI response. This is a transaction over the reviewed local rows only, not WordPress capabilities or external effects.
5. On definitive rollback/failure, the separately committed begin barrier survives; record failure only by an explicit original-owner/epoch-fenced terminal transition. After commit with lost acknowledgement, do not replay the target update: observe both original completion and authoritative target facts. If unavailable/inconsistent, keep unresolved and block grants. Invalidate target and safety option/alloptions/notoptions caches only after confirmed commit; never install speculative success in cache. A later stale cache repopulation is not permission: admission uses raw authoritative rows.

The row lock closes the delayed-writer hole: a paused operation cannot update its target after another process has cancelled/finished its pending token and a later grant has committed. It must acquire and validate the original pending descriptor under that same lock before touching the target. A grant CAS contending with the locked row waits/fails and must still reject a pending/changed epoch. Merely checking pending and then writing the target outside that lock is explicitly forbidden. The in-memory foundation can model these orderings but cannot certify transaction/isolation semantics.

Pending never expires into permission. Crash after begin leaves closure plus pending. Crash inside the transaction leaves either the pending barrier or atomic target/completion; an ambiguous commit stays unresolved until observed. Recovery requires a fresh separately authorized inspect/abandon operation, the same row locks and authoritative target facts. Abandon advances fencing epochs and records closed uncertainty; it must never replay the proposed write or cancel an old process merely by elapsed lease time. A late original writer subsequently fails its token/epoch check. Other pending work is not erased. Missing receipts/read failure cannot prove nothing committed.

While a pending semantic writer already proves admissions closed, unrelated writers/grants reject. A fresh revoke may report an authenticated observation that closure is present, not a newly committed command; it may not replace that pending owner/receipt or unblock it. Closing an actually open grant remains a distinct atomic transition. Emergency invalidation of a pending writer requires the explicit inspect/abandon fence, not a hidden epoch refresh.

## Writer Inventory, ABA and Participation Limits

| Participating surface | Required candidate behavior before activation |
| --- | --- |
| Settings save / site identity | Meaningful `auto_scan_enabled`, cadence, site UUID and scan/queue-affecting source/destination/credential changes close first. Initially treat every settings save as semantic unless explicitly classified safe; no credentials are placed in pending records. Identity creation or changing the fixed site UUID requires a separate bootstrap/scope-migration approval; closure does not grant it. |
| Pairing / opt-in / revoke / origin or key change | Close before changing dependent local facts, retain old binding until confirmed replacement, and never inherit consent. Network enrollment/token exchange is outside the local transaction and remains a separate remote-action gate; failure/unknown remote outcome retains closure and uncertainty. No external replay justified by a local receipt. |
| Polling timestamp / pairing error | Do not close merely for nonsemantic timestamps. Instead lock the safety/target rows in the same order and patch only allowlisted nonsemantic fields from fresh authoritative bytes. Preserve semantic fields and any pending descriptor; stale copied whole-option writes reject. Existing error code paths that also disable the endpoint are semantic and must close first. |
| Schedule apply / legacy wake-ups | Existing remote cron mutation must reject authority/transition mode until a separately versioned integration is proved; consent/writer receipts do not authorize scheduling. Legacy and version-1 evidence semantics stay unchanged. |
| Role/ownership/lifecycle | Fresh request checks protect new commands; logout is not consent revocation. Automatic site-owner/role transfer policy, lifecycle shutdown and writer coordination require separately proved hooks/ordering, not an asserted global interception. Deactivation cannot terminate existing workers. |

Binding compatibility excludes ordinary polling times but includes existing enrollment semantics. For semantic A-to-B-to-A changes, both participating begins/finishes advance durable epochs even if final values/hash match. A stale A-era grant/finisher cannot become current again. Nonsemantic same-field ABA can be irrelevant, but its patch must never restore semantic values. Any writer not inventoried/fenced blocks active-feature clearance. Third-party direct DB writes, old binaries and same-privilege code are outside the cooperating-writer guarantee, not silently controlled by a marker or lock.

Opaque target byte digests are private consistency preconditions only: never log/export them or treat them as credential authentication. Current binding/key material stays inside reviewed local readers; retain no full settings copies in the ledger. No public status extension, dashboard action or execution-eligible projection is introduced.

## Draining, Effects and Downgrade

Closure preserves every claim, native/legacy journal, dispatch owner, original binding/revision/due, lease and effect uncertainty byte-for-byte under a successor-specific validator. Keep their original namespaces; current lifecycle may be draining while current authority/consent is false. Do not rewrite claimed/started work as cancelled, expire it into terminal state, advance due or reassign owners to make validation pass. Initial checkpoint upgrade still rejects unfinished work; fixtures for future closure retention are not permission to create active work.

Close winning before an epoch-bound claim/start must prevent new admission. Work started first may already have effects and needs an independent owner/epoch/effect fence and recovery record; neither this protocol nor a pre-effect read proves cancellation or exactly-once enqueue. The current dispatcher/observer cannot be wired to this successor by changing their schema acceptance. Shared scan facade, raw queue callers, wake-ups and downstream effect reconciliation remain explicit later gates. Upload/abort retain independent policy; closure does not reverse Drime/upload/cleanup effects. Rollback is still rejected regardless of receipt or consent.

No automatic legacy fallback on closed/missing/unreadable state, upgrade, deactivation or error. Preserve unknown/ever-activated/handoff history; no empty journal/option or successful migration proves never activated. Older binaries can run legacy paths despite rejecting a new schema, so an option tombstone alone does not make downgrade safe. Active-mode shipping requires a supported deployment/lifecycle mechanism and explicit verified drain/handoff before downgrade/reinstall; no such mechanism is implemented. Current uninstall can remove other recovery evidence, so destructive cleanup and reinstall are blocked product/ops gates, not repairs performed here. Multisite and restored/cloned database epoch rewind require separate scope/identity design; monotonic counters do not fence an out-of-band restore.

An unwritable database cannot reliably persist immediate cross-process revocation. Do not show disabled after a failed closure or invent an independent emergency stop. Supported readers fail closed on unavailable state, but already-started work/old readable grants remain a risk until the separately proved effect/failure/lifecycle model is complete. This is a shipping blocker for activation, not a reason to enable legacy fallback.
