## Genuine request sequence and non-vacuous oracle

Parent uses real local HTTP requests and bounded in-memory per-user/session cookie
jars. Successful stock wp-login.php POST must issue actual cookies backed by the
owned user/session tables;no HARNESS/BRIDGE wp_set_current_user call,manual trusted
ID,CLI cookie mint,header-to-user override or synthetic authentication success.
Normal stock core's own authentication/user-selection calls remain intact. Carry
Set-Cookie/Path semantics to the same fixed origin;never log cookies/passwords.
Valid HTTP view uses unchanged request_view,and only a capable successful result
may return mode/revision plus wp_create_nonce for the actual action. HTTP POST
passes raw parsed DATA to unchanged request_submit,without normalizing malformed
types,repairing nonce/revision or falling back to the legacy whole-map writer.

Initial finite matrix:13 logical cases,not13 unconstrained arbitrary operations:
view;physical saved;unchanged;stale conflict;anonymous;incapable;missing nonce;
wrong action;wrong user;wrong session;compound nonce;compound site;bad revision.
Wrong-user/session nonces come from genuine views in another capable user's jar
or a second normal login session for the same user. Wrong-action control uses one
fixed proof-only nonce action after genuine capable auth,not arbitrary action or
callback input. All three controls must reject at the ordinary actual action/
user/session boundary. Existing23-case CLI cookie/field coverage remains intact;
do not transplant every CLI mutation into a new HTTP mechanism merely for count.
Use a real view revision r0 for the saved command,then a fresh view r1 for no-op;
submitting old r0 after that successful change must conflict without changing the
new physical bytes. Fixture resets occur out of band only when no request is in
flight,never by altering a captured context or injecting a model revision.

Require physical exact policy map/autoload/revision and sentinel preservation,
one saved acknowledgement,unchanged no-op and stale conflict;all-unavailable or
HTTP200 without these facts FAILS. Independent native/record counters around the

remain explicit. Any uncertain write/unknown cleanup terminates the batch,no
automatic replay or invented uncertainty-success experiment. Fixed response
codes/enums/counts only in retained evidence;nonce/revision/cookies stay private.
