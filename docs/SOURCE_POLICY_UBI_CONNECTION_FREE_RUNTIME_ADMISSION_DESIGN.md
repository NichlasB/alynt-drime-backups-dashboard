## Fresh static-to-engine handoff, not a second pull

A later approved runtime attempt must repeat fresh exact-head/source/config/
ten-layer/static-policy admission and the full graph within **that same owned
attempt**. Do not consume a copied log, persisted packet, previously closed
owner or yesterday's image cache as fresh static authority. Export the bounded
source-held closure view before closing the model; do not reopen its work ledger.
Keep static-source and encompassing runtime-source identities distinct and
freshly constructed, with the latter explicitly including every new consumer,
workflow, serializer and containment-policy source. No recursive implicit source
discovery, caller-selected backend or arbitrary executable/command field.

Ten compressed layers total149,080,417 bytes. A second uncached pull could make
layer payload alone298,160,834 bytes, above the existing256MiB ceiling. Do not
rely on cache hits, quietly give Docker an unmetered second acquisition, or raise
the limit. Select a bounded **verified-byte engine-import bridge** instead:

- Keep the exact verified compressed blobs/config in their owned quarantine
  until the bridge and cleanup finish. Preserve the existing standalone static
  command's unconditional cleanup and no-execution semantics; do not add an
  execution callback to it or spoof its registered workflow identity.
- Propose a small streaming Docker-load archive adapter, fixed to one config and
  ten ordered layers: unchanged config bytes, a single generated image manifest
  without tags, and the ten full layer tar streams. Rehash compressed sources,
  decompressed diffIDs, actual lengths and sequence; source names are fixed digest
  paths, not image-member filenames. Never expand a rootfs on the host, mutate
  config/labels/history, invoke package tools or create an unbounded disk archive.
- Exact engine import format/platform/config-ID behavior is **not proven** by
  current code or this document. Before candidate start it needs source audit,
  synthetic malformed/positive fixtures and separately authorized non-executing
  owned-engine import/readback evidence. Refuse an unsupported format; no generic
  converter, fallback pull, retagged substitute or host installation.
- Count all decompression/copy/readback passes against the existing2GiB logical
  expanded ceiling and shared deadlines, not a fresh per-phase budget. Preserve
  the2,097,152-unit shared parser/model-work limit and2MiB observation capacity.
  Proposed closure-view bound
  is128KiB, charged within existing metadata capacity, not an extra allowance.
  It has at most256 canonical objects and binds actual paths/SHA/size/origins,
  graph/policy identity, snapshot, run/head and the full verified layer plan.

Docker documents [tar/STDIN loading](https://docs.docker.com/reference/cli/docker/image/load/)
and [save/load archives](https://docs.docker.com/reference/cli/docker/image/save/);

assume a manifest RepoDigest survives a load archive. Use the original config

not authorized by human-readable load stdout or a tag.

Create an **unstarted** owned container only after import readback. Require exact
image, user/argv/workdir/healthcheck/security/mount configuration before start.
Using only trusted engine data operations, stream back each distinct reached
canonical file (including both roots) against the source-held closure view before execution:
bounded one-file tar parsing/hashing, no host extraction or candidate helper.
Reject links/sparse/extra members, missing files, unexpected shape, hash/size or
namespace differences. This engine readback/adapter feasibility is unproved now.
No body hash may be invented from the alias-target string or opaque graph digest.

## Proposed container and effect-admission contract

Retain the trusted ephemeral Ubuntu24.04 amd64/manual exact-head environment,
contents:read, pinned checkout, local Unix Docker endpoint and no remote context/
daemon overrides. A later controller/trigger must have its own registered,
default-false version-only identity and finite source closure; the old static
workflow remains static-only and the native SQL workflow remains unchanged.
No generic executor/host binding or new system toolchain is selected.

Propose direct argv (no shell), closed stdin/no TTY, workdir`/`, numeric non-root
runner-derived UID:UID, no supplementary groups/capabilities/privilege/devices,
no host PID/IPC/network/Docker socket or source/config bind mounts, no restart,
no-new-privileges and disabled healthcheck. Override image entrypoint and CMD
explicitly. Preserve the existing512MiB/64-PID/1CPU ceilings, not larger limits.
Read back actual effective image/config/argv and every relevant namespace,
resource, security and mount field; flag construction is not that proof.

Rootfs is read-only. Override the declared `/var/lib/mysql` volume and `/tmp`
with explicit **read-only**, nosuid/nodev/noexec bounded tmpfs mounts, no anonymous
or named persistent volume. Keep their capacities at or below existing256MiB/
16MiB ceilings; do not provision writable data/config/bootstrap state. No host
cache/source mount, sockets, credential environment or SQL stdin. Use only the
admitted image environment plus finite explicit presentation overrides; never
inherit host variables implicitly. Do not claim these controls eliminate all
engine-managed device/pseudo-filesystem writes or arbitrary in-memory behavior.

Official [run controls](https://docs.docker.com/engine/containers/run/) distinguish
entrypoint/CMD, healthchecks and mounts. [Read-only tmpfs](https://docs.docker.com/engine/storage/tmpfs/)
is documented, but target-engine mount support/readback remains to be qualified;
tmpfs is not a secure-wipe guarantee. [Network none](https://docs.docker.com/engine/network/drivers/none/)
still has loopback: no port publication/network attachment is **not** proof that
a process cannot bind or listen locally. Do not report `no-listener=true` from
that flag or a final stopped-container observation alone.

Select **fail-closed effect admission** before any future candidate start:
a container-scoped, source-pinned restrictive seccomp profile must deny socket
creation/connection/bind/listen/accept paths, including supported ABI multiplexer
paths, while preserving or narrowing every existing default restriction. No
unconfined mode, default-ALLOW replacement, added capability, global daemon/host
policy change, FIPS/LSM relaxation or arbitrary user-supplied policy is permitted.
The exact admitted engine/default-profile source, architecture handling, derived
profile bytes/hash and readback must be established before activation. A bounded
subset transformation may remove permitted networking calls from a qualified
default-ERRNO allowlist without adding permissions; unknown rule semantics refuse.

Docker's [seccomp documentation](https://docs.docker.com/engine/security/seccomp/)
describes its default allowlist and per-container overrides, not this application's
effect-denial guarantee. No actual engine/default-policy hash or valid custom
profile is asserted here. If a non-weaker profile cannot be established, execution
remains disabled: do not substitute network:none or install a native wrapper.
Later explicit owned feasibility authority must cover benign positive/denial
controls that distinguish a working filter from a broken canary or CLI error;
any real listener-positive control is confined to an approved disposable canary,
never implicitly authorized for the candidate. Fake flags/stubbed API tests do
not prove kernel enforcement. This design installs or applies no security policy.

## Observation, bounds and cleanup semantics

The first candidate command is version-only. No fallback to root, writable data,
shell, `--help`, default configuration or a second command when it fails. Preserve
normal exit code, OOM/signal/timeout state, bounded stdout/stderr hashes and exact
source/image/run/CID correlation. A safe one-line version literal may be retained
only under a fixed bounded non-secret output schema; unknown/warning output is
hashed/withheld and refused, not logged raw or normalized into an allowed build.
Version stdout is not SQL VERSION() or the driver/core helper identity. Normal
exit and bounded output can establish only the scoped launch observation;
required M/ABI/session/default eligibility remain false/unestablished.

Use a separate bounded versioned evidence schema, not extra fields silently added
to old exact packets: fixed run/head/static+runtime source identities, original
manifest/config and actual engine content/CID/containment-policy identities,
phase/argv identity, byte counts/hashes, normal/timeout/OOM/exit state and distinct
primary/independent cleanup results. Proposed summary ceiling64KiB; primitive
exact shapes/types and finite strings/counts only, no raw Env/inspect/error object.
Copied receipts or caller-provided ready/qualified flags cannot authorize launch;
the fixed source-owned phase construction and actual readbacks are required.

Proposed bounds: candidate15s, aggregate stdout+stderr16KiB, control documents/
inspect1MiB, each engine command at most10s except bounded streaming import120s,
file readback60s, cleanup reserve30s. All share one job deadline inside the current
10-minute runner ceiling; phase ceilings are not additive new allowances. Refuse
start without sufficient remaining cleanup reserve. Preserve acquisition300s,
256MiB compressed and2GiB total logical expanded ceilings. Pipe backpressure,
overflow, partial writes and simultaneous stdout/stderr drainage need explicit
tests; killing a Docker client is not proof its container stopped.

Retain an owner marker and operation identity **before** fallible create/start;
capture full CID before execution, correlate name/labels/image/head/run/attempt
and recheck before every stop/remove. No `run --rm` that loses exit evidence.
After failure/timeout use bounded recovery only for proven owned resources,
with independent always-reconciliation; forced cleanup may complete ownership
release but never makes the failed observation successful. Unknown ownership,
unexpected mounts/volumes or cleanup failure blocks further attempts. No prune,
foreign container/image/volume removal or broad host-path cleanup.

Inventory engine content before import. Distinguish newly imported exact content
from pre-existing/shared cache; do not delete the latter. Remove only proven
owned containers/staging and any independently proven exclusively owned engine
resource, then read back absence. Report residual engine cache separately; no
physical secure-erasure claim. Preserve the original13-file static cleanup in
its own stage; any new runtime marker/profile leaves need an explicit finite
ownership schema, not a permissive extension of that whitelist. All outcomes
must preserve the primary failure while independently attempting cleanup.

Future execution evidence must truthfully mark candidate/image execution when it
occurs, with scope=version-only and **no grant to subsequent execution/SQL**.
It must not overwrite the historical static receipt's false execution fields.
Each newly approved ordered native feasibility attempt must be recorded within
the campaign's remaining native-attempt budget; no counter reset, silent retries
or exemption for an executed failed version probe. Current counters do not move.
