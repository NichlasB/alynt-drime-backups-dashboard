## Implemented dormant contract

- New Query_Context is final/private-construction, create() unavailable. Its
  owned/ambient receivers and source bindings are private and default closed.
  No provider or public test/configuration switch supplies them in production.
- begin() verifies exact receiver/class/method source bindings before invoking
  placeholder mechanics. No callback scanning/adoption, callable/magic/autoload
  probe, same-name subclass exception or snapshot refresh. Checks include the
  virtual placeholder/prepare/escape chain and fixed final dispatch/close guards.
- The context permits at most one exact owned callback and one already-present
  stock-core ambient callback, priority0/accepted_args1. It seals metadata after
  owned warm-up, preserves order/identity, and rejects other-hook changes during
  warm-up. The metadata walk is bounded; malformed/over-budget inputs refuse.
- valid() requires the same ambient global identity, loaded method/declaration
  bindings, sealed query entries and other-hook fingerprint. Simultaneous second
  owners reject; sequential owners release their registrations. A newly added
  ambient callback, third receiver or matching-but-changed descriptor is not
  adopted. Arbitrary query callbacks remain unavailable without invocation.
- No_Reconnect_Connection now has final admit_profile/prepare_checked/close.
  Preparation is checked before and afterward; dispatch checks admission again.
  The adapter's SELECT/strict INSERT/CAS/duplicate-read paths use this boundary
  without changing templates, predicates, acknowledgement semantics or budgets.
  Mutation submission still follows successful preparation, preserving prewrite
  refusal versus post-submission uncertainty. query/db_connect/check_connection/
  execute/print_error remain fixed; core query is delegated, not copied.
- A private explicit native-state field distinguishes never-opened from active/
  closed/unknown. Terminal close attempts only the owned driver once, and
  independently cleans the exact leased callback even on driver failure.
  Unknown closure/removal stays false; only confirmed complete cleanup is an
  idempotent success. An owned/global alias is rejected without closing or
  changing the global handle's ready flag.
- Query cleanup does not call placeholder APIs, remove ambient/moved/replaced/
  foreign callbacks, restore an entire registry, flush cache or repair shared
  state. A pre-existing unleased owned registration is not falsely claimed clean.
  Cleanup failure maps to unavailable before submission or write_uncertain after
  submission, including an acknowledged row; no undo/retry/reconnect is added.
