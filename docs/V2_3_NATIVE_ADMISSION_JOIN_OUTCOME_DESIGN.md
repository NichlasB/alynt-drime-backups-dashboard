## Selected fixed root and private reuse seams

Use one final, test-loaded private owner, no public operation or injected factory,
frame, proposal, actor, clock, callback, endpoint, event certificate or connection.
Future native entry accepts only exact original method and bounded small issuance
body; the raw captured-frame seam remains reflection-only DATA/API test scope.

1. Consume the outer attempt and pin actual POST/core/actor/cookie, original
   borrowed auth mysqli identity/idle physical facts and clocks **before capture**.
   Install role-only option/query/autoload fences before authentication callbacks.
2. Authenticate the original issuance before protected reads. Open one owned
   nonpersistent read-only capture connection, run the existing bounded two sweeps,
   verify unchanged auth/physical identity/clock, and positively close/detach it.
   Equal sweeps are only a candidate, not an atomic admission snapshot.
3. Invoke `construct_registration()` exactly once in that original window. Reuse
   full eligibility/candidate validation and all ten fresh command/operation/
   effect/reservation/terminal/resolution IDs. Verify the full command nonce before
   retaining minimal origin plus **complete** inherited collision set/all ten IDs.
4. Join native candidate/write operations here, before the existing root finally.
   Keep the full proposal/before/after bytes writer-local. Prepare candidate from
   this exact proposal/frame/context; no returned proposal import or second owner.
   Open only a fresh owned writer, validate metadata/policy and renew genuine
   issuance **and** full command guards before BEGIN. Pin original physical auth
   facts around callbacks; no WordPress hooks while owned row locks are held.
5. Preserve the existing fixed order: ten locked comparisons, at most one ledger
   CAS, ten readbacks, original command/window/session checks, COMMIT, release.
   Snapshot exact native event facts at their own observation sites below. No
   producer/queue/settings/safety change, insertion, effect or repair is introduced.
6. Run one idempotent owned-writer cleanup and detach before any diagnostic/core
   callback. Preserve primitive historical facts separately from cleanup status;
   erase full writer data/nonce/native handles. Renew current guards **after**
   qualified release. Success normally closes without a diagnostic. Other paths
   may qualify only under the narrow outcome matrix; this is not read authority.
7. Only a later separately approved read integration may consume the remaining
   original origin once. Otherwise erase it now. Outer finally always closes any
   still-owned resource, consumes all attempts, erases all state and restores exact
   owned filters/role view/error handler; reentry poisons the outer root.

Do not call consuming `admit()`, `retain_native_registration()` or
`construct_native_observation()` as nested successors, reset their latches, use
reflection in runtime code, or expose a continuation between roots. Select narrow
private helper reuse under the same owner instead of copying complete wrappers.
Explicitly disambiguate root phase, writer phase, observer phase, reader/writer
slots and their cleanup names before any future trait composition. Shared names
such as `phase`, `reader` and `finish` must never silently overwrite another owner.
Standalone facades/behavior remain unchanged. Extraction and runtime reuse need
their own approved implementation and regression review; no such extraction now.

## Historical event facts: exact send/ack observations

Proposed private bounded monotone facts are non-authorizing DATA until established
by the actual fixed native root. No caller can submit them to authorize execution.
Use explicit not-attempted/unknown states; missing, false and failed observations
must not be coerced into no-write, no-transaction or released. Retain no handle,
credential, SQL, rows or nonce in an outcome record.

| Fact | Required future native observation site |
|---|---|
| attempt reserved | Consume the one-write ceiling before preparing the fixed CAS; bind/preparation failure still consumes it. |
| BEGIN send/ack/ownership | Mark immediately before BEGIN query; record its return separately; ownership requires pinned session/policy checks, not acknowledgement alone. |
| DML send marker | After successful binding and final fixed candidate/session/budget checks, immediately before the one execute call. `writes===1` is insufficient. Marker means **may have been sent**, never proof that the server received it. |
| DML acknowledgement | Record execute return and exact affected-row result separately, without resetting the send marker after errors. |
| readback validation | All ten exact expected tuples and session/window constraints inside the same owned transaction, before COMMIT. |
| COMMIT send/ack/verified idle | Mark before query; latch true query return before a separate post-COMMIT idle/policy/physical check. Acknowledgement alone is not a verified committed outcome. |
| rollback send/ack/verified idle | Only definite owned pre-COMMIT transaction; mark before the one rollback, latch return separately, then verify idle identity. Never resend unknown BEGIN/COMMIT/rollback. |
| client release | Detach only the exact owned handle; require its observed successful close, no remaining owned handle and consistent ownership bookkeeping. No-handle on an early uncreated path is explicit, not a fabricated close acknowledgement. |
| current acceptance | Fresh original-request auth/intent/physical/deadline checks after release, independently from historical outcome. |

Store historical outcome and cleanup/release as separate slots. A late close or
guard failure cannot rewrite an earlier verified commit into rolled-back/not-written.
A COMMIT return followed by failed idle verification remains an observed ack with
an unverified/uncertain outcome, not silently committed. No `poisoned` phase,
final admission boolean, affected-row count or later receipt substitutes for facts.
Cleanup must not return success from a precomputed PHP return while finally later
fails: choose the final classification only after the single cleanup result is
known. A final retry of finally-cleanup can erase/detach, never promote evidence.

## Outcome, release and diagnostic eligibility matrix

All rows require original-before-DML provenance and complete IDs to have survived
unchanged. Historical classification alone gives no auth, native barrier, retry,
closure, storage, dispatch or execution permission. Any contradictory/out-of-order/
malformed facts consume and erase rather than guessing a more favorable outcome.

| Historical facts | Interpretation | Same-request diagnostic candidate |
|---|---|---|
| No DML marker, no ambiguous BEGIN, no writer created or positively qualified idle/rollback cleanup | `not_written` by this attempt only | No; close/erase. Not permission to retry. |
| DML marker; no COMMIT send; rollback acknowledged and pinned idle verified | `rolled_back` owned attempt | No; close/erase even if earlier execute was unknown. |
| Full readback, COMMIT ack and pinned idle verified | Historical `committed` | No automatic first-lane read. Success closes; any failed guard permanently bars same-root diagnostic. An expanded committed diagnostic policy needs another approval. |
| DML marker, or COMMIT sent, with no fully verified commit/rollback | `uncertain`, never absent/no-write | Potential DATA candidate only if positively qualified client release, original writer window and all current gates pass. No server-quiescence claim. |
| BEGIN acknowledgement/ownership uncertain, or rollback sent without fully verified acknowledgement | Unsupported first-lane cleanup outcome | No; erase/manual reconciliation. Preserve existing DATA transition limits; expanding these cases needs another approval/proof. |
| Any close/detach failure, still-owned handle, lost original facts, auth/physical swap, reentry or expired writer acceptance | Unavailable regardless of historical commit/rollback | No; erase/manual reconciliation, even if root time remains. |

Successful client close is local resource-release evidence, **not** server-side
quiescence. An uncertain writer may finish later; later observer absence is only
`not_observed_at_barrier`, never durable closure or safe retry. Do not query/reuse/
reconnect/ping the released writer or close/configure the borrowed auth connection.
The first native implementation must refuse the uncertain candidate until its
actual same-root provenance and release proof is approved and established. DATA
tests with asserted release facts cannot enable that branch.
Do not clear a failed-auth/intent latch and retry the guard to turn a committed-but-
unaccepted attempt into an accepted diagnostic. Historical committed DATA remains
useful without granting a read continuation, just as the parent rejects fallback
after a failed guard. This conservative first-lane selection expands no authority.

## Clocks, private retention and later read admission

Pin immutable root/writer start before capture; writer acceptance remains strictly
under10 seconds through qualified release/transfer. The existing current
`open_window()` initializes a start; a nested call after capture would renew the
budget. Future integration must establish the window once before capture and
factor internal validation, not call the consuming preparation wrapper afterward.
Root cap20 seconds is the parent's prospective integration ceiling, not implemented
by current `prepare_admission()`. Do not relax that current ten-second proof now.

Only after a qualified writer release inside its original10 seconds may the later
read phase start once: read duration<10 seconds and total root duration<20 seconds,
with nonregressing monotonic/UTC observations and original mutation expiry. These
limits are half-open. Read time does not extend writer acceptance or rescue a late
COMMIT return, and an expired writer cannot get a new20-second window. Native I/O
can overrun; rejection is not hard cancellation or proof the server stopped.

Keep existing origin4096/depth6/nodes256, complete unique ID set at most128 (the
original validator requires at least12 including site/genesis/all ten), aggregate
handoff16384/depth8/nodes512 and smaller request/proposal bounds. Refuse overflow,
aliases/references, altered installation/scope/manifest/proposal/context/IDs; never
truncate, remint identities or reconstruct from receipts/current user/snapshots.

No read nonce or observer is enabled here. The later private policy must genuinely
issue and verify small read intent bound only to this retained command, then issue/
verify the separate full read domain, after fresh current auth and before a fresh
noncolliding lookup UUID/protected read. Mutation nonces are continuity checks,
not replacements for either read nonce. Renew both at claim/pre-BEGIN/post-close;
validate the complete pending-aware ten-row frame after zero-DML barrier release.
No fresh login/request, caller context, imported proof token or durable successor.
