## Selected contract: two immutable layers, one closed request

Keep native history and postrelease qualification separate. The future fixed
private root consumes its own slots only; no caller-supplied frame, origin, actor,
clock, connection, outcome label, callback/provider or successful result port.

1. Retain the existing original origin, complete collision set/all ten IDs and
   exact full writer pin before BEGIN, under the actual original ten-second start.
2. Preserve native transaction/capture/cleanup semantics and one-write ceiling.
   No new parsing, WordPress callback or classification while row locks are held.
3. Complete the existing single owned cleanup. Require capture validity and sealed
   cleanup state before taking a bounded primitive history copy. No reuse/query/
   ping/reconnect of the released writer; borrowed auth is never closed/repaired.
4. Normalize that copy conservatively using the exact raw-return mapping below.
   Preserve historical facts independently of release/current failure. Do not
   mutate, reopen or extend native event positions after cleanup.
5. Keep a separate once-only private qualification record for observations of
   existing final guards. A failed, thrown, expired or unperformed gate cannot
   later become true by retry. No current fact is inferred from a final boolean.
6. Reuse original origin/ID/clock validators and existing pure fact/history/release
   helpers. Check final original pin and deadline after all callbacks, then consume
   the private qualification and erase every retained slot before returning.
7. The first integrated lane always closes locally: diagnostic_candidate_only,
   authenticated, barrier_verified, closure_proven, retry_supported,
   storage_supported, dispatch_supported and execution_supported remain false.
   No small/full read nonce, lookup ID, observer, retry, repair or durable record.

"Closed" here means the request's in-memory lifecycle is consumed and erased,
**not** durable admission closure, server quiescence, rollback completion or a
database receipt proving absence. No qualification object/token survives return.

## Exact sealed-history normalization

Use the existing canonical EVENTS list, no duplicated order or PHP trait constants.
The adapter accepts only the fixed capture shape valid/facts/raw_returns with true
validity. Require genuine owner-side cleanup_done/closed state and no remaining
owned handle before interpreting a qualified client release. A DTO alone does not
prove either condition. Pure DATA fixtures model them explicitly as claims.
Keep these owner-state claims separate from the exact raw map: started/cleanup-
done/sealed booleans, integer tick, and reader/writer/physical-slot remaining
booleans only. All remaining flags must be false; never pass actual handles into
DATA. Future fixed source derives them from its own slots, never supplied claims.

Reject unknown/extra keys, references/aliases, objects/resources, wrong scalar types,
duplicate/out-of-order events, tick overflow and contradictory native/raw facts.
For a valid source capture, nonzero positions are the dense sequence1..tick,
tick<=32. Reuse the current causal event validator; do not parse a second event log.
Raw guard values must still be null and accepted_at0 in the sealed native layer.

| Native source observation | Required normalization |
|---|---|
| No send/detach position and raw not_called | Ack not_sent, ack position0. This is absence of a captured call in a valid owner lifecycle, not a free-standing no-write certificate. |
| Send exists; raw unknown or false | Ack unknown, ack position0. False is not a definite server rejection; never synthesize ack no. |
| Send exists; raw true | Ack yes at a later unique position. Raw true without its matching ack event is contradictory, not a favorable repair. |
| DML not sent | affected_rows not_observed. Attempt reservation alone is insufficient to infer a send. |
| DML sent with unknown ack | affected_rows unknown. No coercion to zero. |
| DML ack yes | Exact observed zero/one/other label; only one plus all-ten readback can precede COMMIT. |
| No writer-created event | No fabricated close success. Only an explicitly captured no-created/empty-handle cleanup path can model no-client release; null capture/slots alone are unavailable. |
| Writer created | Positive detach/close acknowledgement plus empty owned slots and sealed valid ownership bookkeeping required for client release. Physical client close still is not server completion. |

Native adapters reject ack no even though the general synthetic DATA model can
represent it. Preserve raw false/unknown separately, never insert missing events.
Invalid ownership capture is entirely unavailable; not_called inside an invalid
map cannot certify no close/no write. No phase/writes/affected_rows counter or
later receipt substitutes for the fixed native observation sites.

Historical classification uses unchanged pure rules: committed requires commit
ack and verified idle after readback; rolled_back requires observed DML and
acknowledged rollback/idle; a pre-DML verified rollback is not_written; ambiguous
BEGIN ownership or unverified rollback is unsupported; otherwise a DML/COMMIT send
without a verified terminal outcome is uncertain. Release/current state is
independent. Reject malformed maps before interpreting any label.

## Postrelease acceptance: separate record, no seal reopening

The native history's accepted_at0/unknown guards stay byte-identical. A future
qualification record has its own domain/latch and bounded observation order; any
accepted_at-style ordinal belongs only to that record, not the native tick.
A transient normalized DATA projection may join the two for the existing pure
validator, but is a private copy and must be labeled qualification claims, never
an amended native capture or authority certificate.

Only existing genuine postrelease guards can establish current observations:
same original authenticated actor/session/cookie, original method/installation,
independent issuance and full-command intent, pinned original borrowed physical
auth session, unreentered root, unchanged full origin pin and original deadline.
Reuse their actual results at the existing call sites; do not issue extra guards
just to fill a record or reconstruct them from the boolean/receipt/current user.
No failure latch clears. Guards remain unknown when short-circuited/not performed.

Preserve standalone nine and joined ten verification order and one command-nonce
creation. Full writer candidate bytes and local mutation nonce must stay private
until final callback continuity is checked; erase afterward. This clarifies the
parent's broad pre-callback erasure wording: native handles/owned physical facts
are removed before callbacks, but current source needs writer-pin/nonce material
for those final checks. No extra retention beyond the original root or export.

Select the final response only after the one cleanup result and final checks.
Do not precompute a favorable result that finally can invalidate. Outer finally
is cleanup/erase only: no authentication retry, classification promotion, observer
fallback or new work if an earlier failure bypassed normal qualification. Capture
and qualification use separate names/latches from writer phase/finish and from
the synthetic lifecycle owner. Exceptions erase and consume, never remint.
Native-failure branches must not newly invoke final current guards to manufacture
acceptance; their unperformed gates remain unknown. Any later normal-flow factoring
needed to qualify historical failures requires the separate source-integration
approval, never work hidden in an exception/finally path.

## Closed-first outcome matrix

Invalid-origin/ownership refusal overrides all other rows. Close/erase never
asserts that resource release succeeded; the existing fixed cleanup policy still
owns release attempts and its failures remain unavailable.

| Qualified private history | Release/current qualification | First-lane disposition |
|---|---|---|
| not_written or rolled_back | Any | Close/erase; no retry or observer. Keep conservative history only when validly bound to original origin. |
| committed | Positive release and all original current gates | Historical success may retain the existing private boolean contract; then close/erase, no read continuation. |
| committed | Late auth, intent, close, deadline or reentry failure | Unavailable acceptance; do not rewrite raw committed history as rollback/no-write. No retry or diagnostic. |
| uncertain | Even all modeled/current claims true | Close/erase with diagnostic_candidate_only false. General synthetic classifier eligibility does not open this policy gate. |
| unsupported | Any | Unavailable/erase; no expanded unknown-BEGIN/rollback recovery. |
| Invalid snapshot, lost origin/IDs or still-owned handle | Any | Unavailable/consume. Do not return an attributed favorable classification; raw native history is not rewritten before erasure. |

The real unknown-wire/crash path is not established by the joined positive and
reflection-fault proof. Removing the uncertain diagnostic veto requires a new
design/proof approval. Successful current mutation guards would still not replace
either future read nonce domain or a native zero-DML observation barrier.

## Clocks, bounds and sharing

Keep original writer acceptance strictly<10 seconds, nonregressing monotonic/UTC
observations and original command expiry. No fresh clock after capture, cleanup
or classification; no relaxed20-second window in this closed-only lane. Native
I/O overrun rejection is not hard cancellation. Preserve origin4096/depth6/nodes256,
IDs12..128, aggregate16384/depth8/nodes512; reject rather than truncate/remint.
Full writer bytes remain existing writer-local data, not packed into minimal
qualification DTOs. No new persisted schema, package dependency or public contract.

Future implementation reuses existing pure validation and one-shot privacy
contracts, with narrow shared helpers rather than copying classify() or the root.
Keep general synthetic classification and its tests unchanged in meaning; add a
distinct private closed-policy adapter/consumer so synthetic uncertain candidates
cannot accidentally authorize the fixed lane. Reuse the canonical class EVENTS
constant; any pure helper extraction must preserve PHP7.4 compatibility and be
covered independently before native composition. Runtime reflection is forbidden.
