## Findings and admission decision

The [composition foundation](SOURCE_POLICY_REQUEST_COMPOSITION_FOUNDATION.md)
establishes ordinary class-owned construction only in a catalog-rebound API image.
Actual [request_policy](../includes/class-source-policy-trusted-source.php) requires
a nonempty driver declaration; every shipped catalog has driver=null. The root
therefore stops before peers/config capture. Conversely, null is the genuine
internal-mysqli declaration used by the existing private production-origin join,
not evidence that the driver is missing. A non-null synthetic file is not a
native qualification permit. These two meanings must not be conflated.

Select a narrowly approved future **M-only dormant native request admission**:
the existing exact core6.0/PHP7.4.33 source catalog may declare driver=null for
ordinary result-only construction. This is declaration eligibility, not readiness,
authentication, runtime trust attestation or permission to run. Unknown, malformed,
W7.1.3 and L7.1.4 native request rows remain closed in this first stage. Existing
W/L context expectations remain intact for their separately gated qualification;
no implicit support-floor reduction or claim that all required profiles are done.

Do not replace the gate with “any array”, accept caller/environment policy, change
driver=null to a guessed extension path, discover trusted hashes at runtime, use a
Minimum_Lab_Scope, or enable a permissive fallback. No new public create() factory,
hook, route, form, global POST reader or application writer switch is selected.
This does change the dormant internal callable's future native reachability and
must be explicitly covered by its implementation approval; it is not routine cleanup.

### Selected future construction contract

1. Keep the current request reentry barrier before callbacks and the existing
   capability → action nonce → canonical fields/revision → exact site record order.
   View retains capability/type/source/record policy, not a new nonce requirement.
   Definitions are loaded only after record admission; no pre-guard configuration
   capture or owned native allocation. Auth/core reads are accounted separately.
2. Keep request_policy a fixed non-secret catalog decision, with exact core/PHP
   eligibility for the M native branch. It does not inspect credentials, connect,
   borrow the ambient handle, publish a permit or infer runtime readiness. Preserve
   the existing source-bound non-native declaration branch for isolated API tests;
   no runtime input can select that test catalog.
3. Bind the catalog selected by the private root to the context's own later
   code-owned selection. Before declaration/config capture, require an exact
   root/context identity and full catalog equality through a boolean-only internal
   comparison. The context still computes its policy itself: no context policy/
   ready/facts/runtime setter or exported root/catalog/credential getter. This
   closes an explicit root-selection versus context-reselection obligation rather
   than relying solely on today's catalogs being equal by coincidence.
4. Preserve fixed connection → query → context → adapter → provider construction,
   consumed class leases, same ambient identity and receiver/query/core-file binding.
   Leaf allocation is handle-free. Source declarations/pins precede private settings
   capture. The exact context pushes its frame/binding once to its exact receiver;
   consume the attempt before callbacks, with no active-state Reflection or closure
   visibility bypass. No publicly supplied descriptor or alternate composition graph.
5. Use the SAME production join: capture_bootstrap → actual initializer → active
   validation. Exact Linux/x86_64/PHP7.4.33/mysqlnd7.4.33/report0, legacy prefixed
   greeting, transport, session, schema and source checks remain mandatory. The
   pre-connect state authorizes no policy query. Driver=null alone grants none of
   this; actual initialization owns active admission. No native facts imported from
   historical receipts, synthetic controls or the separate trusted-distribution lab.
6. Keep single use, no reconnect/retry, result-only projection, revocation before
   cleanup, credential erasure and graph/static-barrier release on partial failure.
   A saved result followed by uncertain release remains write_uncertain, never a
   promised rollback/success. Ambient core-owned hooks/handles are not ours to close.

The comparison in step3 is proposed, NOT present at this baseline. Existing guards
and source checks are not declared defective or bypassed by this design. The trust
model is ordinary PHP visibility under trusted co-resident code, not containment
against arbitrary Reflection-capable code executing inside the same process.

session cookie; incapable user; action/user/session-bound nonce mismatch or stale
tick; malformed/compound fields/revision; missing/wrong record; source/context drift.

cookie failure cannot vacuously stand in for nonce rejection. No fake clock or
shortened nonce lifetime. Verify guards through separate counters/ledgers: auth
reads are allowed and reported, but owned config capture/native allocation/policy
commands remain zero before authorization/intent/record admission. Invalid cookie
must not establish a trusted user. View is tested under its actual policy.

their actual observation layers; stale-revision conflict alone proves none of
them. Do not repeat selected response-loss experiments or add contention merely
to this first genuine-request proof. Preserve existing uncertain-result contracts
