## Prefix lifetime and same-PID exec design constraints

The successful one-shot owner restores/removes its prefix before returning.
Keeping that receipt,returning a path,skipping finally or adopting owner.json
cannot extend its lifetime or authorize Node to launch. No such edit is made here.

Preferred future composite:the existing trusted Node job controller is the outer
lifetime owner of an exclusively CREATED output namespace,with native captures
registered before child/materialization effects. A dedicated fixed materializer
branch must bind that same origin and captured namespace,close all codecs/sources,
seal and return only bounded DATA. Parent independently rechecks original captures,
membership and all three fixed hashes before any executable mode. This is a NEW
ownership protocol requiring native integration/proof;the current storage adapter
cannot simply be pointed at a pre-existing directory or be granted by JSON.
No marker-only adoption,new general broker or long-lived relay is selected.

For PHP OS limits,prefer one fixed trusted existing-Python exec helper rather than
installing a toolchain or launching uncapped PHP directly from Node. Its only
future operation is fixed role admission,limit set/readback and execve of the
captured absolute PHP with the fixed argv/env. Same PID/start identity across
exec,no persistent broker. Python location/source/profile is a trusted-tool
prerequisite,not selected through candidate PATH. Actual helper feasibility is
UNPROVED;this document does not select a new host tool or implement/execute it.

Register pending child PID/start/session before unmask/observable effects. Recovery
must distinguish the source-bound trusted-helper pre-exec state from the exact
post-exec PHP state,without a broad executable allowlist or interpreting any
unexpected image as success. Require bounded post-exec executable/full-argv binding
before accepting a worker packet. Lost exec/identity/reap/FD/mode result is sticky
Unknown;no guessed PID kill,second spawn or prefix deletion while ownership or
child retirement is unproved. Reconcile captured resources before any next attempt.
A future implementation that cannot provide these barriers stays closed.
