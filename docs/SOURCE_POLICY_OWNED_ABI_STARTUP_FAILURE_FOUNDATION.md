## Implemented scope

The existing [pure contract](../scripts/manual/source_policy_abi_canary_contract.py)
now builds/validates `ADBOWNEDABISTARTFAIL1`. It binds owner context/source hash,
exact image/CID, ABI and builtin/derived policy to the actual fixed Docker
start/attach argv, phase and unchanged15s/4KiB flags **before** message projection.
All authority/qualification/candidate/SQL/production flags are false. No descriptor
can authorize another command, selector, socket, executor or runtime profile.

The frozen finite vocabulary is the design's five reported-layer enums and eight
topic enums. Only the exact `Error response from daemon:` or `Error attaching:`
envelope admits further marker scanning; nested shim/OCI/runc phrases require
their fixed ordered literals. These are source-reviewed diagnostic markers,
not an exhaustive upstream grammar, a root cause or a native capture. Unknown or
version-shifted text cannot qualify execution. Every message fixture is synthetic;
the lost historical message is neither reconstructed nor hash-matched.

Projection is ASCII-only, at most4KiB/16 lines/1KiB per line. It rejects controls,
malformed quoting, oversized input and conflicting chains, masks quoted spans,
paths/URLs/assignments/long identifiers, and matches whole word tokens rather
than substrings inside underscore/numeric identifiers. It emits only closed
enums, never raw or generally sanitized text, paths, environment, policy or
unknown payloads. The scan's instrumented bound is16 input-byte passes plus1024
bookkeeping units. Complete-stream hashes require both EOFs and no truncation;
timeout/overflow/spawn/partial observations cannot acquire complete hashes or
message classification. CLI status/signal describe the observed CLI child only.

The [existing owner](../scripts/ci/source-policy-owned-abi-canary.py) captures the
first failure before releasing buffers and rethrows the original exception.
Status0 with stderr and nonzero status still fail, regardless of marker matches.
A later failure or diagnostic-hook fault cannot overwrite that observation.
Child reap/pipe-close errors remain failures, with secondary cleanup uncertainty
separate from the primary refusal. No fallback, retry or next-ABI continuation
is added. The original outer proof format and failure summary remain in place.

Optional state comes only from the **first existing owned cleanup inspect row**,
after original ownership checks and fresh full CID/image/label validation. Only
status/Running/OOM and an exit code for exited/dead are projected; created/running
default zero is not an exit. Contradictory states are refused. No State.Error,
PID, environment or raw inspect object is copied. A projection fault or exhausted
diagnostic budget cannot suppress existing safe cleanup or trigger another read.

The packet is at most4KiB and charged to existing body-control/observation quotas;
cleanup additions use existing cleanup/observation quotas. Startup15s/4KiB,
native16KiB, body/cleanup512KiB each, observation2MiB, <510s body reserve,
cleanup30s, job10min and summary64KiB remain unchanged. No extra native command,
file/artifact logger, timer, source-cohort member, workflow input or dispatch is
introduced. Native C, syscall expectations, original container-readback guard,
SQL lab, candidate policy and production plugin source remain unchanged.
