## Finite dependency inventory, not a second loader

Keep the two platform manifests/configs and three root identities exactly as
recorded in the static proof; independently pinned core 6.0 is not donor core
6.1.1. Hashes of other dependencies must remain unknown until actually observed.
No mutable tags, alternate distro, compiled replacement, arbitrary executable
path or caller-selected expected hash. Do not edit `ADBLMT1` to pretend it already
contains these observations or overwrite Windows/core-6.0 source records.

For a later explicitly approved inventory proof, select the existing trusted
Docker engine on an owned ephemeral Linux/amd64 CI host. A stopped owned container
can expose the engine-assembled filesystem as a bounded tar stream, without
starting candidate code. Docker documents that [create does not start a container](https://docs.docker.com/reference/cli/docker/container/create/)
but does allocate state; therefore creation/image acquisition requires its own
approval and cleanup, not a read-only exemption. [Export omits mounted volume contents](https://docs.docker.com/reference/cli/docker/container/export/):
it is not evidence about future core mounts, tmpfs or runtime files.

Use fixed source-owned entry/volume/network restrictions, exact CIDs/labels and
`never started` readbacks. Stream only; no host tar extraction, archive-path host
joins or new image overlay/link resolver. Preserve the current tar reader's
literal-name and critical-link refusals; it must not begin following links.
Any separate inventory reader must retain link metadata as untrusted DATA,
never dereference it on the host. Engine assembly does not attest a malicious
engine/host; the existing distribution, kernel and engine trust remain explicit.

Freeze inventory limits before its implementation: two image scopes; at most
64 regular ELF candidates per image / 128 total, 512 dependency edges, 16 graph
levels with a visited set (cycles are not automatically errors), 128 MiB per
file, one file buffered at a time. Keep 1 MiB bounded reads, 1 GiB per export /
2 GiB total and 65,536 entries; retain original acquisition/staging ceilings.
No silent cap increase if the real inventory exceeds this proposal.

Records must bind image manifest/config, effective relative path, regular-file
kind, size/SHA256, ELF64/x86_64/type, SONAME, interpreter and complete direct
dependencies. Paths retain the selected 240-byte/32-segment literal policy.
Edges are image-scoped and refer to exact records; reject duplicates, missing
targets, cross-image satisfaction and unreachable extras. Track interpreter
requirements as well as `DT_NEEDED`. A matching SONAME or graph is only candidate
consistency: it does not emulate search order, caches, aliases, hwcaps, RPATH/
RUNPATH, symbol versions or runtime resolution. Ambiguous/unknown bindings remain
unqualified. Do not use `ldd`, a dynamic loader, PHP or server to collect static
inventory. Required alias/origin evidence must come from the trusted observation
boundary, never guessed path normalization or a file with the same basename.

## Host observer feasibility is the next gate

The parent must observe its own exact candidate process, not hash whatever path
a child reports. Planned identity includes approved head/source image/run,
container ID, actual host PID, kernel process-start identity and namespace/
cgroup binding. Bind before/after snapshots and cleanup; reject PID reuse,
foreign CIDs, stale frames or changing identity. A PID, receipt or environment
variable alone is not source authentication or authority.

Plan bounded host-side kernel mapping observations and hashes of actual mapped
file objects, tied to the separately verified image inventory. Do not open raw
child/map pathnames as host paths. The [kernel proc documentation](https://docs.kernel.org/filesystems/proc.html)
describes access restrictions and mapping-read races; a parsed path list is not
a content digest. [Mapped-file handle access has additional capability restrictions](https://man7.org/linux/man-pages/man5/proc_pid_map_files.5.html).
No assumption that Docker access, container root or an ordinary CI user supplies
that authority. Do not use candidate self-reports as an independent fallback.

Before any candidate loading, separately approve an existing-authority host
feasibility audit using trusted existing tools and an owned harmless child only.
It must establish readable kernel-backed file objects, complete bounded reads,
PID/start correlation, safe observer termination and exact cleanup. No candidate
image, WordPress, database, installation, sudo/elevation, capability assignment,
permission changes or alternate principal is in that audit's proposed scope.
If the existing authority cannot meet this contract, stop at an explicit trust/
scope decision; do not construct a privileged helper or keep polishing DATA
while the physical observer lane is blocked. No feasibility was proved here.

Proposed later snapshot budget: 32 KiB / 256 mapping rows / 64 unique regular
file objects per phase, two fixed startup/final barriers, 1 MiB hash reads.
Require a single bounded maps read at each barrier, anchored by before/after
process identity; reject truncation/instability rather than retrying to obtain
a convenient snapshot. No partial output accepted as complete. Allow
only explicitly reviewed host-profile kernel pseudo-mappings, never a wildcard
for arbitrary executable anonymous/deleted mappings. Bind file identity/digest
and a stable process cohort; these are backing-file snapshots, not an assertion
that every memory byte is immutable or all later dynamic loads were observed.
Access failure, instability, missing origin or over-budget evidence refuses.

## Connection-free launch and observations (later approval only)

Select one PHP candidate container for this phase, not a database daemon or a
two-container TCP proof. Fixed PHP binary from the receipt, CLI `-n`, fixed
absolute mysqli extension and empty controlled INI scan path; do not request a
fabricated `mysqlnd.so`. No shell/WordPress entrypoint/FPM, arbitrary command,
auto-prepend/append, donor CWD/core, arbitrary module or configuration fallback.
Final environment must match an audited source-owned allowlist: no forwarded
secrets, loader injection or PHP override variables. Its complete expected
module/environment list is not yet observed; never invent it from recipes.
Unknown expected profiles block final admission. A later explicitly approved
measurement-only run may collect bounded facts, but cannot self-approve those
facts, become a native grant or be replayed after its process/run has ended.

Preserve non-root fixed owner, read-only root, `network none`, cap-drop ALL,
no-new-privileges, default seccomp and no devices/host-network/daemon socket or
host-proc mount. Fixed read-only source/core mounts expose only the approved
source cohort, not workspace credentials. Override declared volumes with owned
bounded tmpfs, no persistent anonymous volume or writable library/source path.
Propose 128 MiB memory, one CPU, 16 PIDs, PHP memory_limit 64M, 4 MiB scratch and
4 KiB donor `/var/www/html` override, 30-second child/observer deadline with
bounded TERM/KILL cleanup. Output at most 16 KiB per stream / 64 KiB per phase;
drain concurrently and refuse diagnostics, overflow, timeout and nonzero exits.
These are unproved fixed limits, never permission to increase them on failure.

At controlled barriers, require actual PHP 7.4.33 / mysqlnd 7.4.33, CLI Linux
x86_64/64-bit non-ZTS, expected mysqli version, same PHP/mysqli hashes and exact
parent-observed module/backing-file set within the verified inventory. Built-in
mysqlnd must be supported by the pinned executable, clean loading configuration,
actual module/version/client observations and mapped origins; absence of a file
named mysqlnd.so alone is not proof. [ReflectionExtension's documented API](https://www.php.net/manual/en/class.reflectionextension.php)
does not provide an extension-file-origin method; do not invent one or treat
hashing `extension_dir` as proof of the actually loaded module.

Observe initial and final driver report mode **0**, before changing anything;
no call to force a desired default. Require actual mysqlnd statistics at both
barriers, including zero `connect_success`, `connect_failure`, `com_query`,
plus a source audit forbidding connection/handle allocation and SQL calls.
[mysqli_get_client_stats](https://www.php.net/manual/en/function.mysqli-get-client-stats.php)
is client observation, not independent server reconciliation. No credentials,
server process, authentication, SQL, schema, WordPress execution or storage
fixture belongs in this phase. Hash/check genuine core sources without including
them. PHP 7.4 `-n` must not depend on optional JSON: select a finite bounded
ASCII transcript with exact fields/order/types, not a new generic encoder.

Parent expectations must be independently established, not copied from child
claims. Bind head/source image/run/CID/PID/start identity, tuple and inventory
digests, phase and observation digest; reject every mismatch, duplicate/extra/
missing key, coercion, stale/partial frame and unexpected includes. Matching
DATA proves correlation only; no public factory, receiver scope, handle or
activation/rollback grant is minted. Full bounded source includes worker,
controller, observer, cleanup, descriptor, pins and manual workflow/action pins.
No push-triggered native job, manual dispatch or implementation is added here.

Server ELF inventory remains static in this PHP-only preflight. Do not run a
short-lived `--version` command and claim its mapped closure was observed, or
start a daemon just to hold it for inspection. Server startup/storage/loaded
closure, actual full server identity and live/post-exit DB release require later
explicit native-fixture authority and successful observer admission first.

## Acceptance, cleanup, ordering and stop conditions

No always-unavailable pseudo-proof: future isolated tests need independent
positive inventory/correlation cases plus assertion-killed root/hash/edge/type/
bound/identity/phase/zero-activity/observer-absence controls. Synthetic hashes for
unobserved libraries must be labeled synthetic, never written as real expected
image facts. Same-named files, missing loader, changed path/content, unknown
module or incomplete observation cannot pass by matching a child-written list.
Retain original legacy rows, ADBC1/ADBC2, schema/SQL/revision guards and source
pins; native scope and public factories remain absent. No support-matrix change.

Cleanup is required on success, refusal, partial creation, timeout and cancel:
exact owner/CID/process/start identities, zero owned live processes/containers,
mounts/tmpfs/temporary sources and independent post-exit readbacks. No global
Docker prune, broad deletion or removal of shared/pre-existing cache objects.
Report retained image/cache state separately; container removal does not prove
daemon-cache disposal. Do not promise cache ownership or host teardown evidence
that the chosen CI profile cannot supply. Failed cleanup blocks continuation.

Order: existing-authority observer feasibility audit first; only if feasible,
bounded inventory/receipt implementation with synthetic tests, then separately
approved non-starting inventory acquisition/cleanup, then PHP-only connection-
free preflight implementation and approved owned proof. Runtime receiver
integration/native fixtures remain later separate gates. Do not perform routine
cleanup slices to avoid the observer trust decision if that gate fails.
