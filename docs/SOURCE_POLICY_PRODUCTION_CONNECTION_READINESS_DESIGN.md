## Decision: native algorithm evidence is not production connection readiness

The actual fixed adapter has positive native evidence, not merely RAM outcomes:
211 checks/eight groups on the recorded current-core Windows/loopback/strict-mode
profile, with real saved/noop/conflict behavior, non-empty known hooks/core cache,
conservative failures and cleanup. Its public factories and application connection
remain closed. The still-active Source_Policy facade uses the old whole-option
writer; the actual application lost-update repair is therefore **not deployed or
complete**. No more generic counter/cleanup abstraction is selected here.

The next missing evidence is a genuine ambient-core/report-OFF context, followed
by supported-profile qualification and code-owned lazy production composition.
Do not erase those gaps by setting ready/facts, accepting a matching current hash,
using Reflection/manual CLI in production, copying local credentials/endpoints,
or connecting the form to an always-unavailable facade and calling that a fix.

## Reporting mode is shared context, not a connection-local convenience

The public [WordPress db_connect source](https://developer.wordpress.org/reference/classes/wpdb/db_connect/)
sets mysqli reporting OFF before native connection. The archived
[WP6.0 wp-db.php](https://raw.githubusercontent.com/WordPress/WordPress/6.0/wp-includes/wp-db.php)
has the same choice. The [PHP manual](https://www.php.net/manual/en/mysqli-driver.report-mode.php)
documents differing error/strict/default behavior; its
[driver class description](https://www.php.net/manual/en/class.mysqli-driver.php)
describes shared driver state. These primary sources were inspected read-only;
no installed source/site was inspected this turn.

Inference, not a site finding: a normal core-created ambient connection can leave
the request in mode0 rather than the mode3 required by the recent private proof.
That proof deliberately did not call core's connector or alter reporting. Do not
silently extrapolate its exception behavior to false/errno returns in a WordPress
request, and do not toggle/restore shared reporting around the dedicated owner.

Selected policy for future composition: capture the actual reporting posture as
bounded private eligibility evidence, recheck at relevant admission/dispatch
boundaries, and require a qualified mode/profile rather than PHP-version text.
Mode0 and mode3 are distinct qualification rows, not an automatic two-value grant.
Other/changed modes remain unavailable before submission or uncertain afterward;
never reset global flags, call parent db_connect, or retry to regain admission.
Existing private descriptor/checks do not yet implement this added production
eligibility contract; no new accepted descriptor is introduced by this design.

For mode0 qualification, distinguish genuine false/errno1062, syntax and bounded
lock failures from transport/unknown completion. The existing one bounded winner
read is allowed only for definite duplicate evidence on a still-admitted owner;
it is not retry/rebase or proof of whose command committed. Retain uncertainty
for exceptions without definite evidence and for post-commit cache/hook/close
failure. No message parsing, late getter on an invalid handle, reconnect, fabricated
success from a matching row or global error-mode change is selected.

## Trusted context and lazy provider contract — proposed, not implemented

Use one plugin-specific private composition path. No generic backend framework,
settings screen, persistent admission ledger, grant option, environment activation
switch, caller callback/descriptor/connection/table argument or runtime learning
of unknown profiles. A manual source hash/receipt is correlation, not authority.

1. HTTP view: existing manage_options gate, raw site/source validation and exact
   site-record resolution precede owner/context access. HTTP submit: capability,
   existing action-specific nonce, uncoerced field types/source/mode/revision,
   normalized exact record, then private context capture/owner admission. A nonce
   or consistency revision never substitutes for capability/ownership. Compound
   selectors/fields must be rejected before sanitization/coercion; preserve other
   admin actions when the shared dispatcher is deliberately integrated.
2. Obtain database/table/endpoint/charset/flags/credential source from already
   bootstrapped trusted core composition, never POST, filtered option projections,
   copied wp-config, fixture environment variables or an arbitrary object getter.
   Validate exact stock ambient class/declaration/identity before invoking core
   methods. Never borrow/adopt its handle or mutate its session/global reference.
3. Keep credentials private and per operation; no public DTO, logs, revision,
   fingerprint, serialized context or source manifest includes them. Clear owned
   temporary frame/password references on every terminal path. Do not promise
   secure zeroization of PHP copies or modify core constants to erase them.
4. Resolve audited actual core declaration paths, not a fixed modern filename:
   the archived minimum uses wp-db.php. Code-owned compatibility/source policy,
   method provenance and a command-local identity snapshot are separate checks.
   A fresh fingerprint/hash of unknown callbacks or changed core cannot authorize
   itself. Do not execute/autoload unknown collaborators to qualify them.
5. Preserve the finite owned initializer and no-reconnect/check_connection final
   refusals, original command/IO/time bounds, genuine charset/prepare behavior,
   server/schema/autocommit readbacks and ready-last publication. No general SQL
   setup mode or public bootstrap/setter. Move trusted composition inside the
   fixed owner/provider, not a production Reflection copy of manual fixtures.
6. The current numeric-loopback TCP fixture does not qualify localhost/socket,
   IPv6, DNS, remote/TLS, persistent, routed/replica or custom flags. Never parse a
   trusted unsupported DB_HOST into a less secure transport. No DDL/configuration
   repair or global fallback. Actual target support must be established first.
7. Bind only an already-qualified exact ambient core receiver, never a request
   receiver or best-effort adoption of current metadata. Query_Context permits
   at most the exact owned/ambient core placeholder callbacks at their fixed
   priority/argument count. Preserve ambient entries byte/identity-wise and lease
   only the owned entry. Unknown query transforms, all hooks, cache/drop-ins or
   changed relevant graph remain unavailable; no remove_all_filters workaround.
8. Return only the fixed adapter/view/result interface, never the connection,
   setup frame, raw policy row/map or qualification descriptor. One fresh owned
   connection per operation, closed on every path; no borrowed handle, cached
   write session or request-to-request grant. Plugin construction, ordinary
   classifiers, polling and diagnostics do not open it just to read monitoring
   labels. Default/array test fixtures must not gain native authority through
   function_exists or loading a helper.

These requirements can later be implemented in a dormant isolated foundation,
but all public create()/production wiring remain closed until separately approved
and qualified. Eligibility DATA alone cannot mint a native grant; positive tests
must reach the actual guarded construction at their authorized layer.

## One cohesive future application switch

The current call-site map was re-read, not assumed from older paths:

- class-plugin.php and admin/class-admin-page.php construct/share Source_Policy;
  classifier reads must stay ordinary and non-native.
- Source_Policy::set_source_mode still calls update_option for the whole map.
  Keep its public bool signature and documented legacy scalar normalization.
- admin/traits/trait-admin-page-basic-detail-helpers.php currently reads a label,
  posts the existing nonce/source/mode/site and has no revision.
- trait-admin-page-shell.php checks capability; trait-admin-page-actions.php
  dispatches; trait-admin-page-local-actions.php calls the bool legacy setter
  and already maps known safe errors. Its caller must not accept new result
  strings until that actual call is coherently changed.
- Guarded_Entry already defines an unwired explicit submit/view contract with
  exact record matching, action nonce, fixed source/modes and64-hex revision.

After qualification, approve one coherent factory/facade/guarded view/form/POST/
legacy switch, not a partial production activation. Authorized form label and
hidden revision come from one owner view; keep panel eligibility, late escaping,
busy/focus/live feedback and safe notices. Unavailable context renders readable
information with no actionable revision/submit. Never pair a cached classifier
label with a separately acquired authoritative revision. POST requalifies fresh
context and compares before no-op; no hidden retry or automatic refresh/resubmit.

The explicit conditional API returns literal saved/unchanged or safe WP_Error;
the handler rejects booleans/model arrays/objects/unknown strings. Legacy trusted
PHP bool calls use the SAME one-read conditional owner and map saved/unchanged to
true, other outcomes to false; they do not gain stale-form protection without an
expected revision. This is not a new HTTP authorization bypass. Explicit RAM
fixtures remain RAM-only. Remove the unconditional production writer branch only
as part of that approved switch; never retain it as an unsupported-profile fallback.
Preserve option/schema/action/nonce identities; no data migration is selected.

No silently removed save feature on declared supported/deployed stacks: genuine
minimum/intended-profile acceptance blocks release/wiring. If it cannot be met,
stop for an explicit compatibility/product decision, not a minimum-version bump,
unavailable-everywhere facade or unsafe legacy fallback. This design makes no such
product/support change. Unknown/external cache/custom profiles stay unqualified.

## Remaining gates and non-vacuous acceptance

Preferred next gated slice: **Plugin Tester local-only Source-Policy Core-Owned
Ambient/Report-OFF Qualification and Owned Cleanup Proof**. Audit first, exact new
target/owned fixture confirmation, genuine stock ambient core connection in the
private fixture process, unchanged runtime/ADBC contracts and no application
bootstrap/wiring/state. Core's own connector selects its reporting posture in that
owned process; do not simply toggle reporting to make a test pass. Test the actual
fixed adapter with known non-empty observers, preserved ambient callback/handle,
real saved/noop/stale/creator/CAS conflicts, false/errno vs unknown errors and
no replay. Reconcile all server sessions, including NULL/foreign databases:
only exact proved owned ambient/peer identities may be expected, not arbitrary
DB-based exclusions. Require final owned close/live/post cleanup and unchanged
application checksums. Do not reinterpret ADBC1/ADBC2 frames or widen their rules.

Subsequent required gates, not authorized by this design:

1. Genuine minimum-core/native-runtime qualification and read-only intended-target
   profile audit, each with separate target/scope authority. Resolve core source
   paths, autoload encodings, transport, reporting, cache, ambient and callback
   evidence; no install/configuration change just to force the local profile.
2. Code-owned trusted-context/lazy-provider safety foundation using isolated API
   tests, still dormant; then actual owned native/provider proof. No generic new
   abstraction merely to replace the missing real context evidence.
3. Separately approved cohesive guarded form/facade/legacy connection and genuine
   WordPress capability/nonce/record/view/revision/submit proof using only approved
   disposable users/storage/log fixtures. Existing installed state/lifecycle and
   production wiring stay untouched until that exact boundary is approved.
4. Resolve canonical07/07A/security and applicable UI/i18n/Database review evidence;
   run FULL_PRE_RELEASE for the coherent release candidate before packaging or
   publishing it. Scoped proofs do not refresh whole-plugin historical rows.
   Release and live deployment/current backup remain separate approvals.

Every added layer needs a real positive control: always-unavailable must fail.
Capability/nonce/type/record/context failures cause zero protected owner/native
calls; ambient alias/unknown source/hook/report changes fail before allocation or
dispatch. Test changed-mode after submission as uncertainty, no-op/stale ordering,
same-/cross-site/creation conflicts, exact binary/length/autoload predicates,
once-only hooks/invalidation, no retry/rebase and independent cleanup. Required
guard/predicate/reconnect bypasses must kill assertions at the right layer; no
startup error, fabricated ready/facts or test-only success substituted for proof.
Isolated tests are not genuine WordPress auth/storage or native transactions.
