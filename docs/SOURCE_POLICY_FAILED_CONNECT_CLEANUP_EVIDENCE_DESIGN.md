## Decision: proof-local evidence, not a runtime exception

Keep production close(), bootstrap_release(), factories, admission and uncertainty
semantics unchanged. No caller DATA, manual report or counter anomaly may grant
native eligibility, set ready/active, import a handle or resolve write uncertainty.
Do not replace a zero-counter assertion with an unconditional pass, an OR on the
unsigned maximum, a catch-all Error, a skipped case or a fabricated close result.

The future manual verifier must distinguish three source-bound lifecycle classes:

| Case class | Required outcome | Cleanup evidence |
|---|---|---|
| default/wrong-source/all/mode-hook preflight refusal | unavailable, no successful/failed connect or SQL | No allocated native object by audited path/terminal observation; no retained owned callback. Existing unestablished-context close=false is not relabeled a confirmed native release. |
| missing-database initial-connect failure | unavailable, exactly one failure, zero successful connect/SQL/reconnect/reuse/persistence | Exact owned object, acknowledged release, terminal owner state, independent callback cleanup and live/post-exit server reconciliation; failed-state counters are not sufficient. |
| missing-table connected refusal / positive connected setup | Preserve the respective refusal/positive result and all setup/escaping/seal checks | Acknowledged exact owned release, result/callback cleanup and zero live server sessions. Successful-connect active_connections must end at literal string0 in its fresh process. |

Allocation/option/unknown failure states are not silently mapped into one of
these classes. Additional native fault cases need their own approved profile.
Failure before allocation is not evidence that cleanup of an allocated object
works. A successful negative case is not positive native/bootstrap qualification.

## Failure-aware observations and exactly-once release

For the raw reference control, capture the exact native connection exception
class and integer code inside its original catch before any other fallible API.
The currently observed throwing profile requires the expected1049 missing-DB
exception and independently previewed absent target. Never expose message,
trace, SQL, credentials or native object. Do not require mysqli_errno() on an
object whose initialization failed; the observed Error is not an errno receipt.
False/warning profiles remain unqualified until separately specified/proved;
do not switch mysqli reporting mode, reconnect or use another connection as
a fallback to discover the original error.

The actual owner's bootstrap intentionally redacts native exceptions. Do not
invent an owner1049 field from the separate raw control. Its negative evidence
is the actual unavailable result, frozen absent-target composition and observed
one-failure/zero-success/zero-SQL path under the audited source profile.

Allocation establishes identity before connect. Capture the cleanup-attempt
latch before the one native close call. Release must acknowledge literal true
for that exact internally allocated, non-ambient object; false, throw, identity
mismatch, absent acknowledgement or unknown state stays unconfirmed. Never retry
close to manufacture certainty. An Error from a subsequent read probe is only
supporting observation: it cannot distinguish all uninitialized/closed states
and cannot substitute for release acknowledgement and ownership.

For the actual owner, independently require dbh=null, ready=false, qualification
absent, settings/binding/password cleared, terminal state closed, expected query
count and exact callback lease removed. Repeated public close must return cached
truth without another primitive call, reconnect, query or registry repair. The
proof may inspect private state, not stamp dbh/ready/active/facts or import handles.
Preserve independent result and callback cleanup even if native cleanup fails.
Preflight context-close=false remains explicitly distinguished from these facts.

Preserve a primary failure's fixed operation stage/class separately from any
secondary cleanup failure. A last assertion label is not an exception cause.
Reporting failure never skips finally cleanup, becomes a saved/conflict result
or triggers an automatic raw/owner/qualification retry.

## Counter policy: exact observations, no normalization or contamination

Use one fresh private process per fixed case. Require a clean baseline for
successful/failed connection, query/reconnect/reuse/persistent and active counts.
No earlier failed-connect counter state may contaminate later connected cases.
Record raw bounded numeric bytes and native types; no int/float cast of the
unsigned maximum, clamping, modular repair or subtraction of saturated counters.
For bounded small command/result counts, validate exact decimal form and range
before any safe small-integer arithmetic; preserve the16-command upper bound.

Only the precisely bound historical PHP8.5.12/mysqlnd8.5.12 failed-connect row
has the observed post-close string18446744073709551615. Future qualification
must confirm that profile-specific diagnostic shape alongside **every independent
release condition**; the value is never a release acknowledgement. Unexpected
values/types or source/ABI drift block that row, not become a wider allowlist.
Version labels alone are insufficient: preserve qualified declaration/receiver,
driver, endpoint, hook/cache and source bindings for the selected row. This
design supplies no new distribution-authentication or native source proof.
Other runtimes, signed/floating/scientific representations and nonwrapping rows
need their own evidence; the diagnostic formatter's synthetic acceptance does
not qualify them. Raw explicit_close/implicit_close counts are observations,
not substitutes for a successful native close call.

Keep literal-zero active-count acceptance for cases which successfully connected
and for no-attempt preflight cases. No wrapped-counter exception applies there,
even if other terminal fields happen to match. Preserve exact connection/result
counts, six bounded metadata frees, no implicit/unbuffered result leak, positive
string round trip, changed-seal refusal and all once-only/no-replay controls.

## Independent reconciliation and fixed per-case orchestration

The future manual controller runs the existing seven allowlisted cases in their
existing order, serially, at most one child per case. Raw reference observation
is separate and never counted as the owner positive. No arbitrary case/script,
command, endpoint, SQL, retry queue, connector framework or production backend
switch. Existing CLI/prefix, runtime/driver, source pins, hook and credential
gates remain before site/native effects. Children inherit the approved private
credential environment, never secrets in arguments, output or persisted records.

Require a quiescent, exactly confirmed local MariaDB instance for this first
proof. The controller uses the resolved bundled mysql client for out-of-band
read-only reconciliation, separate from candidate command counters. Count **all
server sessions except the observer's own**, including DB=NULL or a different
selected database, and active transactions. Filtering only DB='local' could miss
a failed-selection session. Existing historical local-only counts are not
retroactively described as this stronger observation. Do not read/log other
sessions' SQL/user/host payloads or kill foreign sessions; foreign activity makes
the proof ambiguous and blocks progress rather than being cleaned up.

For physical acceptance, inspect the server while the child is still alive
**after** acknowledged owned/callback cleanup, not only after process exit.
Use one bounded proof-private stdio hold/acknowledgement, then normal exit and a
second reconciliation. No relay, listener, new network endpoint, elevation,
Build Tools installation or OS security framework. The held child may not
perform further database work or reopen; it only accepts the one release token
for its current case/run and exits. Zero sessions after process death alone
cannot turn a missing/false close acknowledgement into confirmed cleanup.

A fixed source/profile/case/run-correlated terminal record must precede the
hold. Validate one record and the expected child exit; reject missing/duplicate/
truncated/out-of-order records, nonzero exit, wrong correlation or extra case.
These are local orchestration DATA, not authenticated grants or production
provenance. No native object/resource or callable crosses the channel. The
controller acknowledges only after independent live reconciliation succeeds;
failure leaves the case unconfirmed and stops the cohort, never reruns it.

Proposed implementation caps:16KiB stdout/4KiB stderr per case,128KiB stdout/
32KiB stderr per cohort, fixed record schema and bounded scalar lengths. Test
these limits without buffering unbounded output or relying on PHP7.4 -n JSON
availability in synthetic workers. Preserve the existing20s bootstrap,2s connect/
3s read,16 native-command and25s whole-case-cohort envelopes. Count child startup,
preflight, hold and inter-case checks against the cohort deadline; no per-child
reset to expand it. If the finite profile cannot meet those bounds, stop for a
separate resource decision. Clock checks do not prove hard interruption of a
blocked synchronous API. Timeout, pipe failure, crash or forced termination is
unconfirmed cleanup, never successful release; owned-process/fixture recovery
requires its approved scope, not a broad PID kill or a skipped reconciliation.

## Non-vacuous implementation and later native acceptance

First implement only manual-harness contracts and isolated API/IO fixtures.
Native execution, real native-worker/stdio feasibility and SQL reconciliation remain
separately gated. Proposed acceptance must exercise actual code paths, not a
verifier supplied with every success flag already true:

- A real synthetic positive owner reaches setup/active then acknowledged close;
  the complete case cohort passes. Always-unavailable/always-closed stubs fail.
- Expected native exception1049 is captured before any invalid failed-object
  getter. A stub getter that records calls and returns a plausible code must
  assertion-fail if wrongly invoked; unexpected exceptions cannot pass as1049.
- Failed-connect wrap alone, zero counters alone, zero sessions only after exit,
  forged/missing/false close ack, wrong/ambient object, retained result/callback,
  uncleared frame, second primitive close or source/profile mismatch all fail.
- Successful-connect wrap fails; dirty child baselines fail; a failed case cannot
  alter the next case's counters. The known wrap plus full failed-case evidence
  can exercise only its explicitly selected profile, never promote another row.
- Simulated live DB=NULL sessions and foreign activity block acknowledgement;
  callback cleanup and process exit cannot hide them. Missing live observation
  cannot be replaced by a terminal process count.
- Virtual pipes/clocks exercise record correlation, output caps, no duplicate
  child/retry, timeouts, primary/cleanup error retention and secret redaction.
  Guard-removal controls must produce assertion failures, then exact source
  hashes are restored before final clean QA. Tests must not pass only because
  an exception or worker startup failed.

Later owned native proof requires fresh target/fixture/process confirmation and
audit-first approval. It must qualify the actual per-case process/hold protocol,
genuine error/source profile, raw failure-aware observation, negative owner
cleanup, connected failure and positive setup/escaping/cleanup. Retain77-table
preservation/owned-fixture cleanup and complete support-safe evidence. No design
or isolated test qualifies WordPress6.0/PHP7.4, installed utf8 configuration,
deployment hosting, physical transaction atomicity or full Database Review.
