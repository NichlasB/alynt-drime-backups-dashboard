## Implemented behavior and ownership

`bounded_access_policy` defaults false. Its distinct CLI and environment value
require both alias and ELF policies; malformed/inconsistent combinations refuse
before owned creation/network. Old `policy_flags` retains its two-value contract;
the three original modes retain their scanner/parser choices and successful-work
charge. The new mode does not silently replace or retry the strict1MiB policy.

The manual workflow alone performs read-only Git HEAD/source checks, preserving
the Python entry's no-child-process boundary. It compares the expected checkout
and all eight fixed source paths before new-mode acquisition. The same paths are
frozen/read back by the entry. Source hashes are freshly derived, never copied
from an old diagnostic. This is reviewed fixed-job construction, not a Python
object or report authenticating itself, and not an interpreter/runner build pin.

After metadata admission one actual authority binds manifest/config, all layer
identities, current source/head, run+attempt correlation and the original deadline.
Layer0 attaches one model only after complete verification and actual alias
profile admission. New-mode application retains only compact metadata/ELF/binding
envelopes, never ten full layer record dictionaries; it does not replay-charge
already settled parser work. Final namespace and both selected-root pin checks
precede owner-bound graph closure. Reporting cannot spend or reopen the owner.

Cross-import ELF metadata/graph refusals are translated from the helper's exact
loaded exception class into the known entry domain, preserving finite cause and
validated, deep-copied bounded facts. Arbitrary class names are not authorization.
The accounting packet validates exact keys/types, existing caps, valid states,
bounded counts and work=parser+model+grants+settled+burned. These are DATA consistency
checks, not evidence that an external receipt performed a real invocation.

Source readback, accounting, cleanup and reporting failures are independent.
Cleanup is attempted against the target-admitted root even if construction never
returned an owner handle. Partial/invalid markers or unknown membership refuse
and retain; owner=None never implies artifact absence. The existing cleanup
function's root/UID/0700/head/run/regular-file/single-link/thirteen-leaf checks and
non-recursive deletion body are unchanged. Cleanup spends no modeled work and
does not require a healthy owner/deadline. First failure is retained, and failed
reporting cannot emit a successful process result. Independent always cleanup is
preserved and now explicitly fails if its entry file is absent rather than
silently treating skipped reconciliation as success.

No manifest/config/layer/root pin, parser policy, provider/alias/feature/cycle
constraint, aggregate work/object/byte/time limit, strict reader, download/TLS
client, model/authority behavior, runtime PHP or dependency contract changes.
The runner, timeout, read-only workflow permissions, pinned checkout, disabled
credential persistence and non-cancelling concurrency group remain unchanged.
