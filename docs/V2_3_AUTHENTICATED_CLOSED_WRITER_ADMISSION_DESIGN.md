## Approved Plan and Decision

Versions remain dashboard `0.1.77` and uploader `0.5.25`. Clean committed Git baselines are the source recovery points; no site backup or restore is needed.

Plan: map the actual adapter/store/proof boundaries; choose a closed successor and versioned intent/receipt contract; specify authoritative context, admission lifetime and transaction coupling; review provenance, privacy, counters/capacity, concurrency/ABA and lifecycle; validate unchanged relevant regressions and repository QA; commit/push and verify exact-head CI. Do not add executable tests for behavior that this design does not implement.

Prefer a new default-off closed admission boundary and separately validated successor, not relabeling schema 6, widening the old request adapter's purposes, promoting its fixture nonce or converting a schema-6 `finish()` result into authenticated success. Separate **current user authorization**, **durable closed provenance**, **transactional target completion** and **execution eligibility**. The first implementation remains in-memory/test-only; real WordPress construction/storage proof and production integration are later approvals.

## Closed Scope and Concrete Purpose Contract

Initial writer scope is deliberately **disable-only**: a fixed existing settings target, exactly `auto_scan_enabled: true -> false`. No posted target option/table, callback, SQL, arbitrary patch, credential, site UUID, connection field or replacement binding. Already false is a fresh no-op observation only with valid current closed state, null pending and matching freshly authenticated context; it is not a permission renewal or fabricated target write. A stale issued command or another pending owner cannot be acknowledged as a no-op merely because the bit is now false. Enabling scanning, cadence changes (including model cadence names versus actual settings recurrence names), connection/pairing writes, queue/upload/cron and all other writers remain separate gates. Even disabling this real option needs separately approved production integration; no current handler is changed here.

Candidate request contract: `closed_writer_request_v1`. Reserve distinct action prefixes `alynt_drime_backups_closed_writer_issue_v1`, `alynt_drime_backups_closed_writer_command_v1`, and `alynt_drime_backups_closed_writer_receipt_v1`; these strings do not exist in the runtime. A request cannot select its provenance/domain. Grant, enable, activate, dispatch, rollback, generic rebind and posted finish purposes reject before private context reads or sink calls.

| Purpose | Server-issued facts and permitted result |
| --- | --- |
| `upgrade_closed` / confirm `close` | Existing strict schema-6 source digest and original site/binding/permission epoch; explicit closed-only upgrade, no target write or missing-row bootstrap. |
| `begin_disable` / confirm `disable` | Fixed settings-disable descriptor, authoritative before/after byte digests, private context digest, original epoch and deadline. One closed pending begin CAS; any dependent target completion belongs to the same verified request's internal continuation. |
| `abandon_closed` / confirm `abandon` | Fresh independently authorized intent for one original pending ID, its closure generation, current expected epoch and freshly inspected target facts. Same locking protocol; no target replay or automatic expiry-based clearing. |
| `receipt_read` / confirm `observe` | Fresh read intent with its own request ID/deadline and a separate observed command ID. Bounded private observation only, independent of the old command's expired deadline or superseded epoch. |
| Internal completion | **Not a form purpose or public sink accepting an observed hash.** Only the fixed transaction owner may construct it from locked authoritative target bytes after the exact conditional write. |

For the first three envelopes the exact common normalized fields are `contract`, `purpose`, `command_id`, `site_uuid`, `enrollment_binding`, `expected_generation`, `issued_at`, `expires_at`, `confirm`. Add only: `origin_digest` for upgrade; `context_digest`, `before_hash`, `after_hash` for begin; `operation_id`, `closure_generation`, `context_digest`, `observed_hash` for abandon. The fixed writer/target/field/desired-false descriptor is derived from purpose, not body parameters. `receipt_read` instead has exactly `contract`, `purpose`, `command_id`, `site_uuid`, `observed_command_id`, `issued_at`, `expires_at`, `confirm`, with no current epoch requirement that would prevent later observation. Each submitted body adds only `nonce`.

All form leaves are scalar strings, at most 2048 bytes; reject total raw or unslashed canonical form over 4096 bytes, extra/missing keys, arrays/objects, malformed UTF-8 and coercion. Unslash once; parse canonical nonnegative decimal strings with overflow checks before casting, lowercase canonical UUIDs/digests, exact enums/confirmations and bounded positive UTC. Server clock/UUID supply issuance; `0 < expires_at-issued_at <= 300`, no client clock, future issuance, regression, overflow or renewed expiry. Command nonce binds a domain-separated SHA-256 of the entire typed envelope in the fixed listed order, independent of submitted field order; this digest is not a signature or authorization. Read nonce uses the separate receipt prefix and binds the complete read envelope, not just the old ID. Core nonce lifetime never extends the independent deadline.

Issuance itself is POST-only with current authentication/capability and a purpose/site-specific issuance nonce before any private read. Its small form accepts only purpose/confirmation/issuance nonce, plus the selected original operation ID for abandon or receipt observation. The server reads/rederives all context, epochs, hashes and closure facts; it never trusts echoed author/role/source/eligibility/provider fields. Recheck authorization and issuance nonce after context read before minting the command nonce. A valid nonce authenticates intent to the current session, not permanent authority.

## Authoritative Context and Admission Construction

The future reviewed construction path must fix the single-site scope, existing table/option identities, raw readers, core authentication implementation, clock, nonce domains, strict store and transaction connection. No public constructor that accepts arbitrary truthy authorization/context/consume ports becomes a production factory. Unit seams are explicitly test-only and cannot mint real authenticated provenance; PHP same-privilege code/database administrators are outside the security sandbox claim.

Before every private read and every begin/upgrade CAS attempt, independently revalidate the actual logged-in cookie/session, current site-scoped `manage_options` and exact nonce/purpose/deadline. Do not rely on a cached current user, user-submitted actor, old capability result or nonce alone. Recheck after authoritative context observation. No new capability, user/role change, stored authentication token or automatic session modification is introduced. Another currently authorized administrator can inspect/abandon site-owned pending work using fresh intent; possession of an old operation ID is not admission.

Context reads existing raw non-autoloaded safety/settings rows, validates strict supported decoded data without object instantiation, verifies an already valid site UUID against the fixed scope, and derives canonical before/after bytes for the exact disable-only delta while preserving every unrelated field. Bound target raw bytes to 1 MiB and decoded depth to 16; PHP-serialized settings need an object-disabled decoder and recursive rejection of objects/unsupported shapes, not an unsafe generic unserializer. Never call identity-generating/default-installing getters, use merged defaults as evidence, normalize corrupted state or rebuild an absent row. Historical enrollment binding is retained closed; unavailable/invalid old pairing blocks future grant eligibility, not closure recovery. A missing/corrupt target remains unresolved rather than justifying repair or an unverified abandonment.

The private context digest binds a version tag, fixed site/target/writer, historical binding, exact current permission epoch, source-state consistency digest and exact before/after target bytes through opaque digests. It excludes observation time, actor and ordinary polling timestamps except when those timestamps actually change the full target bytes being conditionally written. Current private raw values stay inside the provider/transaction and are not persisted or returned. Issuance facts are rederived at consumption and then again under locks; target ABA by cooperating writers advances epochs even when final bytes match.

Before begin compare the original issued context/epoch. After a confirmed begin, reauthenticate immediately before transaction entry outside locks, but validate the **expected closed successor** (original epoch + 1, same pending owner/delta/target precondition), not impossible equality with the pre-begin whole-state digest. Do not rewrite the original envelope/epoch/deadline to achieve that check. Construct one stack-scoped, single-use continuation bound to the original verified intent/delta, pending ID/closure epoch, fixed connection and deadline. States are begin-confirmed -> transaction-entered -> terminal/unresolved; it is invalid after return/finally, cannot be retained for another request, refreshed after expiry, constructed from posted flags or replaced by a Boolean. This object conveys reviewed local admission only, not an execution permit or durable identity. Role/session changes after the final pre-transaction check are not atomic with row locks and remain an explicit residual race.

## Proposed Successor and Non-Promoting Provenance

Schema **7** is a candidate implementation allocation, never accepted by existing validators. Preserve schema 6 unchanged. Avoid recursively nesting a full mutable successor or discarding its receipts: proposed root keys are `schema_version`, `generation`, `enrollment_binding`, `schedule_revision`, `claims`, `authority`, `dispatch`, `lifecycle`, `legacy_writer`, `writer`. Keep protected binding/claims/authority/dispatch and lifecycle history unchanged and consent/authority false, lifecycle disabled. No new active work, grant pointer or eligibility.

`legacy_writer` is the complete original schema-6 `barrier` group, with all original keys, typed values and ordering frozen, including its single schema-5 checkpoint, old upgrade, current/retained fixture receipts and null pending. `writer.origin` retains the original schema-6 generation, schedule revision, permission generation, changed-at time and canonical source digest. Together with unchanged protected root fields these reconstruct the exact typed schema-6 snapshot; validate that projection with the unchanged strict schema-6 rules through a bounded read-only snapshot validator, not relaxed source acceptance or rereads of changing storage. No second full checkpoint or archive-of-successor is stored; the old checkpoint remains at the same JSON depth. Canonical digest uses fixed structural key order, deterministic receipt-map ordering and preserved ordered lists/types for hashing only, never rewriting the frozen group; it is consistency evidence, not proof of past authentication. CAS still compares the exact original raw bytes. The schema-7 wrapper is not a promise to retain the original whole-row JSON whitespace/encoding, only the complete validated original typed state and its canonical digest.

The exact proposed `writer` keys are `source`, `origin`, `upgrade`, `authenticated_grant`, `authenticated_receipts`, `internal_receipts`, `fixture_receipts`, `pending`, `closure`, `completion`. Source is candidate `closed_writer_admission_v1` for the reserved real lane and `closed_writer_admission_fixture_v1` for the test-only lane; only the fixed trusted construction path selects it. Authenticated grant stays null. Real new authenticated request receipts use reserved `authenticated_closed_writer_v1`; transaction-owned completion uses separate `internal_closed_writer_v1`; simulations remain fixture-domain. The real constructor rejects fixture-lane state/nonempty new fixture receipts; the fixture constructor cannot populate real authenticated receipts or use the real internal domain. IDs, command digests, original/result epochs, commit times and ledger purposes are immutable. The current closure and completion carry the corresponding exact domain and are distinct mandatory records; a closure never certifies target success. Pending includes the original begin identity, original/closure epochs, immutable bounded descriptor, receipt reference and a server-reserved internal completion UUID allocated once before the begin CAS attempts. Reject collisions across all retained/reserved identities; retain this completion UUID across attempts, never accept it from the form. No raw delta values, credentials, cookies, nonces, session verifiers or unnecessary actor identifiers. A row's source marker is not historical authentication evidence against a privileged writer and is never reusable request admission.

Migrate only an explicitly authenticated, strict existing schema 6 with null pending and no unfinished/uncertain protected work, matching original site/binding/epoch/digest. Reject unsupported/missing/corrupt/autoloaded source, cross-domain identity collision, unavailable context, exhausted reserve or current pending without repair or cleanup. Earlier schema 3/4/5 must first use their separately approved closed path. One guarded CAS preserves all old evidence, advances all three counters once, and records only the new upgrade's provenance; it does not authenticate old fixture receipts or infer never-activated history. An exact retained upgrade replay observes only, never resets later state. No getter, read intent or constructor migrates.

First test-only implementation uses a distinct `closed_writer_admission_fixture_v1` lane: simulated authentication/ports and its receipts cannot populate `authenticated_receipts` or be accepted by the future real constructor. Reserved real-domain receipt construction remains denied until the separately approved real-core factory/storage proof. This is deliberately not certification by mocked `authorize() => true`. The candidate schema must keep test/authenticated/internal records disjoint and validate that distinction; no test flag accepted from a request switches lanes. Detailed serialized projection/receipt validators and exact maximal fixtures must pass review before persistence implementation, not be inferred from this prose.

Keep the existing 128 KiB encoded-state bound, JSON depth 16, 1024-byte per-new-receipt bound and minimum 4096-byte closure reserve. Budget **50 optional historical receipts combined** across frozen schema-4 history, frozen schema-6 history and new authenticated/internal/test history, not fifty per namespace. Frozen/current mandatory last/upgrade/closure/completion slots are additionally bounded within the byte cap; they are never evicted to admit another command. Reserve the terminal slot/capacity before begin and include worst-case new provenance in measured reserve. Upgrade requires four available increments; begin three; terminal two, leaving closed reserve. Every new persisted transition advances storage/permission/revision once with a contiguous validated chain and nonregressing bounded commit time; no overflow/reset, epoch refresh, pruning or automatic pending expiry. Full history may block subsequent begin; unavailable persistence cannot guarantee emergency closure.

## Same-Connection Admission and Recovery Rules

1. Validate/authenticate the original purpose, exact fixed delta, current source/context and capacity. A no-op is observed without renewing permission; no target write follows an unconfirmed/failed/unknown begin. At most three actual CAS write attempts retain original ID/epoch/deadline, each with fresh authorization/context after reads and immediately before the write, never silent reissuance. Count attempts, not guard invocations: the old fixture adapter's three-call guard budget must not be silently treated as three read-plus-write retries. Ignore generic truthy sink returns; only the fixed reviewed backend's validated durable outcome can support an acknowledgement.
2. Commit closed begin first. Authenticate again immediately before the bounded transaction and create the one-shot continuation. Reject unsupported engine/cache/drop-ins/reconnect behavior or nested transactions; no fallback to separate writes.
3. On one non-reconnecting connection lock safety first, fixed target second, then validate strict successor, original pending/closure/epoch/site/binding, exact current target bytes, derived delta, current clock and original deadline. Recompute the candidate result from those bytes. The pre-lock context is not permission to skip these checks. Do not invoke WordPress authorization hooks, HTTP, cron, queue, logging or arbitrary callbacks under locks.
4. Conditionally write only the fixed target and persist internally constructed completion/removal of that exact pending owner in the same transaction. Recheck clock/deadline before commit. Report committed target outcome and publish/invalidate reviewed caches only after confirmed commit; the developer native proof's cache bypass does not prove a production cache provider. Revalidate response authorization outside locks; if it is lost after commit, deny/redact the response without claiming rollback or deleting committed evidence. A freshly authorized administrator may reconcile it. Supported readers use raw rows despite stale cache repopulation.
5. A definitive abort keeps the separately committed begin/pending closed. An uncertain COMMIT/acknowledgement is unresolved until fresh authorized receipt plus raw-target observation; never replay a target write, create a new ID or claim disabled/nothing-happened from missing evidence. Pre/post-COMMIT process proof is not server power-loss or dropped-COMMIT-packet proof.
6. Fresh abandon uses identical safety/target locks and exact pending/closure/current epoch. Revalidate freshly inspected target facts; only original before/after states can be recorded without a separate repair policy. It advances fencing counters without replay or erasing other work. An expired old begin is not permission, and an old paused writer fails after abandon/new begin/ABA. Unexpected target state, missing completion with inconsistent facts or read failure stays closed/unresolved; no forced recovery is implemented.

The three-CAS retry budget applies to upgrade/begin outside the target transaction. Locked completion/abandon use one original-epoch transaction attempt with fixed pure continuation/clock/state predicates, not a call back into WordPress authorization for every internal SQL statement. No implicit transaction restart or refreshed intent follows a timeout/deadlock. This preserves the explicit post-authentication role/session race rather than violating the no-arbitrary-hooks-under-lock rule.

Fresh receipt reads authorize before private lookup, then revalidate authentication, read nonce and independent deadline after observation before returning, and return only bounded current/superseded/not-found/unresolved results for their exact domain. Command consumption first validates current authentication plus the exact original envelope/nonce/deadline, then looks for an exact retained ID/digest/domain in strict current storage. A match observes without mutation even if its old epoch/context is superseded; only a genuinely new mutation proceeds to fresh context/epoch equality and repeated write guards. Expired consumption rejects even if the receipt survives. Changed purpose/digest/site/domain conflicts; legacy IDs cannot be relabeled. Read intent has its own short window and never renews an old command. Secondary outcome (not attempted/committed/abandoned/unresolved) is separate from closure outcome. Dispatch/execution flags remain false; these flags do not mean that a future approved local settings transaction has no database effect. No public status/support export of private state, digests, receipts, target bytes or authentication material.

## Focused Review, Required Proof and Remaining Gates

Reviewed failure boundaries: source-label promotion, arbitrary injected ports, stale user/session/nonce, cross-purpose/site/body substitution, hidden bootstrap/defaulted context, pre-lock checking without serialization, target/checkpoint ABA, pending expiry, duplicate replay, partial writes/lost acknowledgement, nontransactional/reconnecting storage, speculative/stale cache success, counter/history/byte overflow and unknown activated/lifecycle history. Current source remains closed; this design proposes no bypass or weakened test.

Concrete review corrections: post-begin context must match the expected closed successor, not the old pre-begin whole-state digest; retries count write attempts, not the old adapter's individual guard calls; exact retained-receipt observation precedes current mutation-context equality; real constructors must reject the test lane; no-op cannot bypass pending/stale context; lost response authorization cannot undo or erase a committed transaction. These are requirements found during source-backed design review, not fixes or executed runtime results.

First foundation acceptance must cover zero-I/O default-off construction; exact bounded scalar parsing/unslashing/canonical action; all disallowed purposes before private reads; three-attempt original-intent guards and invalidated retained continuations; test versus reserved real provenance separation; strict finite schema-6 reconstruction and unsupported/malformed sources; frozen receipts/checkpoint preservation; migration/no-op/duplicate/domain conflict semantics; locked-context admission contract; capacity/counter/clock edges and failed/unknown outcomes. Simulated sinks prove only contract behavior. They do not certify real authentication, SQL serialization of this new schema or production target mutation.

Later owned Plugin Tester proof must exercise genuine core sessions/capability loss and fresh receipt reads **together with** the new successor/continuation/backend, including session loss before transaction entry, lock waits, late writer after recovery, failed/lost writes, cache behavior, provenance collisions, unsupported environments and independently audited cleanup. Separately gate disposable users/storage creation; keep actual users/options/cron untouched. Do not join two historical proof receipts into this missing integrated proof.

All participating production settings/connection/timestamp/lifecycle writers, scope/identity migration, network enrollment, effect ownership/draining, legacy cron paths, supported cache/DB environments, deactivation/uninstall/downgrade/restore and any enabling/grant transition remain shipping blockers. Row locks do not cancel already-started effects or constrain nonparticipating writers/old binaries; logout alone does not revoke durable consent, and unwritable storage cannot promise global immediate revocation. The previous broad design's limitations remain binding. No dormant-only release is warranted. Use focused auth/architecture/concurrency/error/lifecycle reviews per implementation; run the applicable full feature/pre-release/security/package suite only before an integrated release, followed by separate deploy/enablement approval.

Implementation-plan progress: this chooses the concrete non-promoting closed-admission bridge after the physical writer proof; it does not open execution. **Recommended next gated slice: local-only V2.3 Closed-Writer Admission Contract and Provenance Safety Foundation**, default-off/test-loaded with disposable in-memory fixtures only. Implement the parser/admission lifetime, finite closed successor projection/receipt segregation and deterministic failure/interleaving contracts; keep real authenticated provenance construction, actual users/options/SQL/cron, grants, production wiring, activation and rollback disabled. This crosses a new storage/request interpretation boundary and requires separate implementation approval; no generic cleanup or release substitutes for it.
